# ADR-001：OmniSpace AI 从零实现架构决策记录

- 状态：已接受（Accepted）
- 日期：2026-08-02
- 决策者：入职工程师（本人）+ 本地检查路径
- 依据文档：项目2.2.txt（技术规格）、项目2.2测试.txt（全量测试用例）

## 1. 决策问题

在实机环境（RTX 4060 Laptop 8GB / 32GB RAM / Python 3.10.11 / torch 2.13 CPU-only / 无模型权重 / 无 Redis Server / 有 npm 网络）下，如何从空白仓库严格实现项目2.2规格，并使全部契约可实机验证。

## 2. 目标 / 非目标 / 约束

### 目标
- 严格按规格 §4.1 落地 13 个路由模块、80+ REST 端点、统一响应信封 `{code,message,data,request_id}`、错误码 40001-40015
- 落地 §4.1 WebSocket 协议（8 种客户端消息 / 15 种服务端消息，2s 系统状态广播）
- 落地 §4.1 全部数据库表（SQLite + sqlcipher3 AES-256，机器特征派生密钥）
- 落地 VRAM Manager（pynvml 真实遥测 + Best Fit + 互斥 + 内存缓存 LRU）与 GPU 统一管理器（基准测试 + 三档配置）
- 落地四队列任务调度（gpu:1 / cpu:2 / io:4 / training:1，priority DESC，手动10/确认7/自动5）
- 前端按 §3.1/§3.2/§3.3 落地 Sakura 主题、侧边栏 7 导航、分镜表 11 列、3D 导演台、SSE 对话
- 全部第三方前端库本地化（离线可开，COM-002）

### 非目标
- 本会话不下载/训练任何模型权重（规格要求权重预置 models/，空白仓库不具备）
- 不实现 PyInstaller/Inno Setup 安装包构建（规格冲刺 E，依赖完整功能验收）
- 不引入构建链（规格 §6.2 明定 React UMD + Babel Standalone 形态）

### 约束（实机实测）
| 项 | 实测值 | 来源 |
|---|---|---|
| GPU | RTX 4060 Laptop，显存 8188MB，已用 2574MB | pynvml 实测 |

| RAM | 32GB | Win32_ComputerSystem |

## 3. 决策与备选

### D1 进程拓扑：单进程 FastAPI 单体（127.0.0.1:8765）
- 备选A：微服务拆分 —— 否决。无独立扩容/发布/爆炸半径需求，违反 monolith-first。
- 备选B：桌面壳内嵌多进程 —— 部分采纳：GPT-SoVITS 按规格保留独立进程适配点（引擎门控，未启用）。
- 规格符合性：§6.1 部署架构即单机单体，Launcher 守护为后续包装层。

### D2 任务队列：原生 asyncio 四队列 + Celery 语义适配层
- 决策：自研 `core/task_queue.py`，四队列并发度（gpu=1/cpu=2/io=4/training=1）、优先级（手动10/确认7/自动5，priority DESC, created_at ASC）、暂停/恢复/取消/重排、断点记录 pipeline_progress。
- 备选A：安装 Redis Server + Celery —— 否决。Windows 非原生支持（微软弃维护端口），引入不可审计运维依赖；实机无 Redis。
- 备选B：Celery + SQLite transport —— 否决。丢失优先级与 Chain 语义，与规格 §2.3 不符。
- 适配点：`TaskQueue` 接口与 Celery `apply_async/chain/revoke` 语义一一映射，未来有 Redis 时整体替换实现、契约不变。
- 可逆性：双向门（接口隔离）。

### D3 数据层：sqlcipher3 真 AES-256
- 决策：使用已装 sqlcipher3，密钥 = PBKDF2-HMAC-SHA256(机器GUID+用户SID, salt, 100k)，hex key 注入 `PRAGMA key="x'...'"`。
- 备选A：明文 SQLite —— 否决。违反 §6.1 L3 安全架构与 COM-004 用例。
- 备选B：应用层字段加密 —— 否决。只保护字段不保护全库，低于规格。
- 失败策略：密钥派生/迁移失败时拒绝启动并写日志，不静默降级明文（修正历史教训：宁可显式失败）。
- 可逆性：单向门（库级加密迁移成本高），经 `tools/export_plain.py` 提供受控导出缓解。

### D4 AI 引擎：六引擎适配器 + 三条件就绪探测，未就绪返 40002
- 决策：`core/engines.py` 定义 Qwen2VL/SDXL/AnimateLCM/GPT-SoVITS/TripoSR/MiDaS-YOLO 六个适配器；就绪 = 权重文件存在 ∧（需CUDA者）CUDA可用 ∧ 显存预算通过；任一不满足 → 端点返回 40002 模型未就绪 + detail 说明缺什么。
- 备选A：mock 推理输出 —— 否决。用户明示"实机测试，拒绝沙箱环境"，伪输出属造假，且污染 LEARN 训练数据闭环。
- 备选B：CPU 小模型兜底 —— 否决。torch 为 CPU 构建但无权重文件；规格无 CPU 推理路径。
- 解锁路径：权重按 models/README.md 放置后，引擎探测自动转就绪，无需改码。
- 可逆性：双向门。

### D5 前端样式：手写 CSS 变量实现 §3.2 全部设计令牌
- 决策：`src/styles/tokens.css` 1:1 实现规格色彩/字体/间距/圆角/动效令牌 + 组件类（.sidebar/.btn-primary/.card/.storyboard-row 等）。
- 备选A：Tailwind 运行时脚本 —— 否决。体积大、不可审计、离线首次加载违反 COM-002 精神（虽可本地化，但无构建链时 utility 类与规格组件类双轨并行徒增复杂度）。
- 备选B：引入 Vite 构建链 + Tailwind —— 否决。违反 §6.2 UMD 形态约束。
- 可逆性：双向门（接入构建链后可回迁）。

### D6 前端框架与依赖本地化
- 决策：React 18.3 UMD + Babel Standalone + Three.js UMD（r149，最后一个含 three.min.js 的稳定线），经 npm 拉取后拷贝至 frontend/libs/，index.html 仅引用本地路径。
- 备选：CDN 引用 —— 否决，违反离线约束（§1 constraints.inference=完全本地推理 与 COM-002）。

## 4. 系统映射（数据流 / 依赖方向 / 信任边界）

```
浏览器(React UMD) ──HTTP/WS──> FastAPI(127.0.0.1:8765, 激活中间件, 统一信封)
                                  │
               routers/* ──> core/engines(就绪探测) ──> models/ 权重(缺失→40002)
                                  │
                     core/vram_manager <── pynvml 真实遥测(RTX 4060 8188MB)
                                  │
                     core/task_queue(4队列) ──> pipeline_progress 断点表
                                  │
                     core/db(sqlcipher3 AES-256) ──> data/omnispace.db
                                  │
                     core/ws_hub ──> 2s system_status 广播 + 15种服务端消息
```
- 依赖方向：routers → core → 外部资源；core 不依赖 routers。
- 信任边界：仅绑定 127.0.0.1（§6.1 L4）；插件执行经 RestrictedPython 沙箱门控；所有文件路径校验防穿越。
