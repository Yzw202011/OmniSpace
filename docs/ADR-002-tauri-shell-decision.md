# ADR-002：Tauri 桌面壳决策——裁剪，维持浏览器 + launcher 形态

- 状态：已接受（Accepted，裁剪）
- 日期：2026-08-20
- 决策者：TASK-P2-06 工程整改（用户批准的任务清单预写裁决方向）
- 关联：要求#38（基线 A.5）/ RTM A-01 / ADR-001 D1（单进程单体拓扑）/ docs/deployment-manual.md §1

## 1. 决策问题

要求#38 规定 Tauri 2.x 桌面壳（安装包 <500MB）；实际交付形态为 launcher.bat 拉起后端（127.0.0.1）+ 系统默认浏览器访问。RTM A-01 长期悬置为 ❌（降级实现未定案），需二选一正式落档：排期落地 src-tauri 骨架，或明确裁剪。

## 2. 决策

**裁剪 Tauri 壳**。以「launcher.bat + 系统默认浏览器」作为正式交付形态，不再是"临时降级"。

## 3. 理由

1. **单机交付已闭环**：launcher 启动后端 → 健康检查轮询 → 自动开浏览器；RC 目录交付验收全部在浏览器形态下完成，无用户反馈要求桌面窗口。
2. **壳层增量价值 ≈ 0**：Tauri 提供的系统托盘、自动更新、安装包分发均不在"单用户/单机/离线"场景需求内；本项目核心价值（本地推理、显存管理、字段级加密）全部在 Python 后端，壳层无增益。
3. **成本与铁律冲突**：需引入 Rust 工具链（离线环境不可审计依赖，违反内嵌 Python 零系统依赖约定）、src-tauri 骨架、WebView2 适配、`tools/build_rc.py` 交付流程重构；对 16GB 显存单机项目属于纯支出。
4. **#38 前提失效**：<500MB 安装包与实际交付形态（模型资产 193GB 本地目录 + RC 目录直拷）不兼容——本项目分发单元是目录而非安装包，安装包体积约束失去锚点。

## 4. 后果

- RTM A-01：❌ → **⚪ 合理化豁免**（本 ADR 为证据），不再是悬置项。
- 基线要求#38 关闭为豁免；`要求#38 安装包<500MB` 随裁剪失效，交付体积约束改由 RC 目录 + 模型清单（RTM M 系列）承载。
- 放弃的收益（诚实记录）：桌面级窗口体验、系统托盘常驻、离线自动更新、商店分发能力。
- 前端不受影响：Hash Router SPA + 静态资源由 FastAPI 根路径服务，未来若重启壳决策可零改动套入 WebView。

## 5. 重启条件（可逆门）

出现以下任一情况时重开 ADR：

1. 需分发给非技术用户或经应用商店分发；
2. 需系统托盘常驻 / 桌面通知 / 自动更新等桌面集成；
3. 浏览器形态出现硬瓶颈（多 WebGL 上下文限制、大 3D 场景性能墙）；
4. 多实例/多 GPU 进程生命周期管理需求。

## 6. 验证

launcher.bat 冷启动 → `/health` 通过 → 浏览器自动打开 → 对话/绘画/视频三链路手工验收通过（RC 交付流程已多轮执行，见 docs/deployment-manual.md §5）。
