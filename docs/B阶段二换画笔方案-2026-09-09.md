## 0. 大白话总览

**一句话：给漫剧换一支能「看着三张参考图画画」的新画笔（Qwen-Edit-2511），让角色/场景/道具三图硬锁合成成为可能——这是分镜一致性（你最大的痛点）的最强武器。**

**先说一个重要发现（2026-09-09 前置核验 ✅）**：原计划的 nunchaku 加速件在 Windows 上**暂时装不上**——
| 轮子来源 | 最高支持 torch | Windows？ |
|---|---|---|
| 官方稳定 v1.2.1 | 2.11 | ✅ 有（cu12.8/cu13.0×cp310~313） |
| 官方 nightly v1.3.0dev | 2.12 | ❌ 仅 Linux |
| **我们 ComfyUI 环境** | **2.13.0+cu130** | — |

torch 2.13 的 Windows 轮不存在（连 Linux 都只到 2.12），降 torch 会破坏 ComfyUI 0.34 的配栈。
**好消息：GGUF 路线完全绕开 nunchaku**——city96 的 ComfyUI-GGUF 自定义节点（社区标准件）+ Unsloth 官方 Qwen-Edit-2511-GGUF 权重（[HF 已发布](https://huggingface.co/unsloth/Qwen-Image-Edit-2511-GGUF)，ModelScope 镜像同步）= 零新 Python 依赖、任何 torch 版本可跑、与现有 klein GGUF Q6_K 管线同族。

**三步走**（每步独立拍板/独立回退）：

| 步 | 干什么 | 比喻 | 粗估 |
|---|---|---|---|
| B2-1 | ComfyUI-GGUF 节点安装 + Qwen-Edit-2511 GGUF Q4_K_M 权重落盘 + ComfyUI 冒烟（单图编辑→三图 EditPlus） | 给画笔换笔芯 | 下载 ~11G + 半天 |
| B2-2 | 关键帧三图合成双路由（ComfyUI 新道 vs 现有 klein+PuLID 道）+ 固定剧本一致性基准实测 | 新旧笔各画一幅对比 | 1~2 天 ⚠️ |
| B2-3 | 按基准数据拍板主力 + 淘汰件退役（进一件退一件）+ Z-Image 快车道（可选，按余额） | 选定主力笔、旧笔入库 | 半天 |

**明确不做**：nunchaku NVFP4 路线（等官方出 Windows torch2.13 轮后再评估——零改动可后补）；对话/VL 守门不动（阶段一已收）。

## 2. B2-1 组件安装与冒烟（第一步，纯加法）

> **B2-1 执行记录（2026-09-09 13:00~13:35，✅ 管线通但速度是硬伤）**：
> **管线全通 ✅**：ComfyUI-GGUF 节点（git clone city96 + pip gguf 0.19.0）→ 四件权重（Q4_K_M transformer 12.3G + VL-7B 编码器 4.5G + mmproj 1.3G + ComfyUI 格式 VAE 0.24G）→ 挂接 20 项硬链接 → 单图编辑出真图（896²，626KB）。**六轮排障**（五坑归档见下）。
>
> **速度实测（诚实口径）**：
> | 指标 | 值 | 对照 klein-9b |
> |---|---|---|
> | 冷启动（装载+首张） | 716 秒 | 15 秒（GGUF 装载）|
> | 纯生成（20 步×~34 秒/步） | **11 分 18 秒** | **27 秒** |
> | VRAM 峰值/稳态 | 15.7GB / 11.4GB | 15.1GB / 14.1GB |
> | 磁盘 | ~18G | 8.5G |
>
> **25 倍速差的原因**：20B（vs klein 9B）× GGUF 全反量化（无原生 int4 kernel，vs klein 走 ComfyUI DynamicVRAM 原生管线）——方案预警兑现（"GGUF 走 dequant 非原生 kernel"）。**nunchaku 的 SVDQuant 原生 kernel 本可 3× 提速，但 Windows torch2.13 轮不存在**。
>
> **定位重估（待 B2-2 数据后拍板）**：11 分钟/张 → 仅适用「多资产难镜」（方案原定位）或离线批量。日常分镜维持 klein 不动。**B2-2 的关键问题从「新笔能不能画」变为「新笔画 11 分钟值不值」**——如果三图合成的一致性增益足够大（如 DINOv2 场景锚 0.85→0.92+），难镜用 11 分钟可能值得；否则维持 klein。
>
> **五坑归档（下轮复用）**：
> ① `LoadImage` 不认 base64，须落 ComfyUI input 目录引用文件名；
> ② `ImageScaleToTotalPixels` 需 `upscale_method` + `resolution_steps` 两必填参数；
> ③ `TextEncodeQwenImageEditPlus` 单输出（负面条件须 `ConditioningZeroOut` 生成，不能 `["6",1]` 越界取）；
> ④ **mmproj 文件名必须包含 encoder 名**（如 `Qwen2.5-VL-7B-Instruct-mmproj-BF16.gguf`——loader 按 `encoder_stripped_name in mmproj_filename` 匹配，纯 `mmproj-BF16.gguf` 匹配不到 → 维度错 720×1280 vs 3840×1280）；
> ⑤ **VAE 必须 ComfyUI 格式**（diffusers 官方仓的 `diffusion_pytorch_model.safetensors` 是 3D 卷积格式，ComfyUI `AutoencoderKL` 拒载维度不合——须从 `Comfy-Org/Qwen-Image_ComfyUI` 取 `qwen_image_vae.safetensors`）。
>
> **三图合成（B2-2 核心）已于 09-09 14:24 冒烟通过 ✅**——320 秒（暖启动）产出真图（845KB 896²），角色+场景+道具三图合成管线全通。速度比单图冷启动（716s）快一倍（页缓存暖）。指标：peak GPU 15.7GB / peak commit 44.1GB。
>
> **V8 回归 klein Errno 22 根修（09-10 00:20，✅）**：14:04 起 klein 在新栈装载失败——**根因不是 torch 而是 tqdm 进度条**（`pydeps/tqdm/std.py:446` 的 `sys.stderr.flush()` 在 Hidden Window 长跑后端上句柄坏 → OSError [Errno 22] Invalid argument）。修复=src/main.py 头部禁用 tqdm/HF 进度条（`TQDM_DISABLE=1` + `HF_HUB_DISABLE_PROGRESS_BARS=1`）。修后 klein 27 秒出图正常——**B2-2 双路由对照组已解锁**。
> **战场已还原**（ComfyUI 停、GPU 2GB、端口清）。冒烟脚本入库 `tests/unit/eval/qwen_edit_smoke.py`。

### 改动清单
1. **ComfyUI-GGUF 节点安装**：git clone city96/ComfyUI-GGUF 到 `tools/ComfyUI_windows_portable/ComfyUI/custom_nodes/ComfyUI-GGUF`（纯 Python 包，无编译依赖，对 torch 版本无要求 ✅）
2. **权重下载**（三选一渠道：HF 直连 / ModelScope 镜像 / 夸克网盘）：
   - `Qwen-Image-Edit-2511-GGUF` Q4_K_M 档 transformer（unsloth 发布，~11G）
   - text encoder（Qwen2.5-VL 7B int4/fp8 档 ~4-8G，ComfyUI-GGUF 有对应 GGUF 档）
   - 落盘 `models/paint/qwen-edit-2511/`（进一件退一件记账）
3. **模型挂接**：`_mount_models_before_spawn()` 硬链接挂 ComfyUI models 目录（零改动——挂接机制是通用的）
4. **冒烟脚本**：`tests/unit/eval/qwen_edit_smoke.py`（独立脚本直提 ComfyUI /prompt，不动产品链）

### 影响面
- ComfyUI custom_nodes +1 目录（ComfyUI 启动扫描多一个包，冷启动 +2~3s）
- 磁盘 +19G（权重+编码器）；**同窗退役对冲**（见 B2-3）
- 不碰任何产品代码/路由/引擎——纯加法

### 验证方法
1. ComfyUI 冷启动无报错（custom_nodes 加载日志）
2. 单图编辑冒烟：输入图+指令「把头发改成蓝色」→ 产物真实落盘 + 目测正确
3. **三图 EditPlus 冒烟**：角色 portrait + 场景图 + 道具图 → 合成产物（这一步验证「三一致性」的技术可行性）
4. 显存峰值采样（ResourceSampler 现成）——Q4_K_M 预期 10-12G，与对话互斥由现有 sleep/wake 管

### 风险与回退
- **GGUF 过饱和问题**（[社区已知](https://github.com/Comfy-Org/ComfyUI/issues/11476)：GGUF 档输出可能过饱和）→ 冒烟目检；若 Q4_K_M 明显过饱和换 Q5_K_M/Q6_K 档（+3~6G 磁盘）；VAE 与 2509 同 hash 可复用
- **GGUF+fp8 编码器混搭的缩放漂移**（社区报告轻微 zoom-in/out）→ 编码器也用 GGUF 档对齐
- 回退 = 删 custom_nodes 目录 + 权重目录（记档 rm，纯加法零残留）

## 3. B2-2 三图合成双路由实测（核心交付）

### 改动清单
1. **comfy_paint_engine 新增 Qwen-Edit 工作流模板**（`qwen_edit_workflow.json`）：EditPlus 节点（三图输入组：character/scene/prop）+ GGUF loader 节点 + 现有输出/落盘链复用
2. **gen_router 双路由**（关键帧/资产图入口）：
   - 多资产镜（asset_ids ≥2 且含 character）→ 路由 Qwen-Edit 三图合成
   - 单资产/无资产镜 → 维持 klein+PuLID 现链（零改动）
   - 路由开关 config 化（`manga.keyframe_engine: auto|klein|qedit`，默认 auto）
3. **一致性基准**：固定 3 角色剧本（现成 mystery3d 包 ✅）× 两路由各跑 8 镜 → DINOv2 场景锚 + VLM 三一致分项（人物/场景/道具）出对比表

### 影响面
- keyframe.py 入口加路由分支（~40 行）；comfy_paint_engine 加工作流（新 JSON 文件）
- **现链代码零改动**（路由是「加一条路」不是「改一条路」）——回退=开关切回
- 显存：Qwen-Edit 10-12G 与 klein 8.5G 同级，互斥/让渡管线复用

### 验证方法
1. 单镜双路由各出 1 图 → 目检 + 计时
2. 固定剧本 8 镜双路由全跑 → 一致性基准表（对比表入 docs/）
3. 全量 pytest + 三闸
4. 让渡链回归（画 Qwen-Edit 期间发对话 → 排队 → 恢复）

### 风险与回退
- 20B 编辑模型单张可能几十秒（未实测 ⚠️）→ 若 >90s/张则路由规则收紧到「仅多资产难镜」
- 三图合成质量不达预期 → 数据说话后维持 klein 主力（这就是双路由的意义）
- 回退 = config 开关 `keyframe_engine: klein`
