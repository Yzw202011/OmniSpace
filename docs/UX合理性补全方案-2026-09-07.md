## 一、问题定性

### 1.1 现象与根性（大白话）

项目功能层是齐的（后端端点、接口函数大多都在），但**界面层零散跟进**：哪个模块催得紧哪个模块补两下，没有统一的产品规范。结果就是用户批评的样子——分格上写着「v2」却回不去 v1、图点不大、生成中不能停、删除按钮认不出来。

根性不是「缺几个按钮」，是**「生成物卡片」这类最高频的交互对象没有统一设计**。漫画分格、漫剧关键帧、角色资产卡、绘画历史——它们本质是同一种东西：「AI 生成的一个产物 + 用户对它满意/不满意的处置」。处置操作集应该全项目一致，一处学会处处会用。

### 1.2 两套自查清单（长期规矩，本次起每个改动/新功能先过）

**用户思维五问**：
1. 我怎么发现它？（可发现性——纯图标按钮连产品负责人都认不出=不合格）
2. 我不满意怎么办？（四件套齐不齐：**回上一版 / 重新生成 / 取消进行中的 / 删除**）
3. 出错了怎么办？（报错带出路——项目已有铁律，保持）
4. 等待时我知道在干嘛吗？（进度可见 + 可取消——分钟级任务必须两者都有）
5. 下次来它还在吗？（持久化——现状已达标项，核查即可）

**开发者思维四问**：
1. 同类断点别的模块有没有？（先 grep 同款再动手——漫剧关键帧与漫画分格是同一个断点）
2. 后端已有能力前端接了吗？（本次实锤：rollback 端点+API 函数都在，界面零调用）
3. 会破坏既有行为吗？（未命中操作集的路径逐比特不变——安全网铁律）
4. 将来扩展会被卡住吗？（操作集做成数据驱动的统一组件，新模块（如将来的云端生成物）零成本套用）

## 二、统一规范：「生成物卡片操作集」

全项目所有展示 AI 生成产物（图/视频/文本产物）的卡片，操作集统一为：

| 操作 | 交互 | 依据 |
|---|---|---|
| **放大预览** | 点卡片图 → 全屏 Lightbox（Esc/点背景关） | 用户五问 1/2：看不清谈不上满意 |
| **版本历史+回退** | 版本徽标（v2）可点 → 历史版本横排 → 「设为当前」 | 用户五问 2：抽废不丢（后端旧版保留设计本如此，UI 没兑现） |
| **重新生成** | 文字按钮，title 注明「换种子再抽一版，旧版保留可回退」 | 用户五问 2 |
| **取消进行中** | 生成中遮罩上常驻「取消」按钮 | 用户五问 4：分钟级任务不可取消=绑架用户 |
| **删除** | **文字+图标、危险色**、确认弹窗 | 用户五问 1/2：可发现性教训 |
| 生成中状态 | 遮罩+进度+预计时长（现状已有，保留） | 用户五问 4 |

**组件形态（开发者视角）**：新建 `frontend/src/components/common/GeneratedArtifactCard`——把上表做成数据驱动（插槽：媒体/版本列表源/重生成回调/取消回调/删除回调），三个模块共用一套 DOM 与 CSS，不是复制三份。后续新模块（云端生图结果等）直接复用。

## 三、落地范围与后端能力对账（先查后做，不重复造轮子）

| 落地点 | 操作集缺口 | 后端端点现状 | 本批工作量 |
|---|---|---|---|
| 漫画分格（ComicWorkspace） | 版本回退/放大/取消/删除文字化 | rollback ✅ `keyframe.py:2575`、版本列表 ✅ `:2620`、队列取消 ✅、行删除 ✅ | 纯前端 |
| 漫剧关键帧（Storyboard 编辑器） | **同款断点**：版本回退零暴露 | 同上（同一组端点） | 纯前端（同组件复用） |
| 角色资产卡 | 替换图有；历史版本无（历史端点已存在 `asset/{id}/history`） | 历史 ✅（上限 12 条） | 版本横排接历史端点 |
| 绘画历史 | 重新使用参数有；删除/收藏无 | 待查（批内先对账再定） | 对账后定 |

范围裁定：本批做前三处（组件复用摊薄成本），绘画历史先对账、随批 B 排期。

## 四、验收标准（真浏览器实弹，非单测绿）

1. 三个模块的卡片操作集**行为一致**：同一套手势（点图放大/点徽标出版本/取消遮罩任务）三处行为相同；
2. 漫画分格：真点开 v2 的版本抽屉看到 v1、回退后徽标变 v1 图片切换；
3. 漫剧关键帧同样回退一条真数据；
4. 生成中真点取消，任务停、卡片回生成前状态；
5. 删除按钮文字可见、确认弹窗流程不变；
6. 组件复用验证：三处卡片 DOM 结构一致（抽查 class 树）；
7. tsc/eslint/vitest/构建全绿 + 既有测试零回归。
