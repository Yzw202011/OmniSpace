## 〇、模式判定：一次打包+分销，现有架构恰好为此设计（诚实定性）

**「包无身份，码有身份」**——这正是仓库现状：

- **包 = 锁死的保险箱，泄露低危**：整树 Cython 源码全灭；未激活则业务 API 全 403
  （真中间件，`src/main.py:516-532`）；IP 资产（h3 工作流/风格种子）出包即密文，
  密钥藏在编译后的锁芯里（`asset_vault.py`）。一份母版发全网，谁拿到都一样、
  没码都用不了。
- **码 = 按台发放的钥匙，才是真货币**：Ed25519 验签 + 指纹 2/3 绑定（一号一台）、
  换绑代数（旧码随吊销名单死）、绝对到期日、解绑墓碑、公钥双藏、时钟回拨守卫、
  错峰巡检。发码台账已记 AES 加密的 customer/contact（`license_console/store.py`）
  ——分销记账有地基。

由此三条诚实推论：

1. **每买家水印路线废弃**（一次打包=没有每买家包）；按**分销商**打渠道水印降级
   为 P2 可选（份数少可行，泄露可溯源到渠道；且门禁生效时安装包泄露本就低危）。
2. **铸币权=Ed25519 私钥，绝不离手**：v1 口径=分销商不自助发码——分销商收集
   买家指纹+订单 → 你用发码台出码 → 买家激活。自助发码=锁芯 v3 多公钥改造，
   单独立项拍板。
3. **激活链=本模型的每买家控制核心**：它从未实弹跑过（R8「激活🔶」、10-02
   「⚠️待窗口」）——必须大演练。**吊销名单触达用户的唯一通道=升级包**（差分
   自动下发），所以升级链演练与激活链同等重要。
