## 3. 实机硬件安全防护设计（零信任 + 最小伤害原则）

### 3.1 GPU 防护（依据文档 B §4.1）
| 防线 | 阈值 | 动作 | 实现位置 |
|---|---|---|---|
| 显存四区 | <80% 安全 / 80-90% 警戒 / 90-95% 危险 / >95% 溢出 | fp32→fp16→bf16/int8→强制 int8 + 卸载非活跃 LoRA→卸载基座启用 CPU Offload | engines/vram_manager + scheduler |
| OOM 拦截 | CUDA OOM 异常 | 自动卸载非关键模型，任务标记失败不崩溃 | inference/* |
| 温度墙 | >85°C 降频 / >90°C 暂停生成 + UI 警告；连续 3 次降频锁 80% 利用率 | services/thermal_guard 状态机 |
| 功耗墙 | 触及 TDP 且温升 | Batch Size 减半 | scheduler |
| 采样节奏 | GPU 2s / CPU 5s / 磁盘 10s 分级采样 | 防监控自身成为负载 | scheduler/monitor |

> 注：显存四区阈值按 BK-023 裁决对齐文档 B §4.1（config.yaml: gpu_vram_warning=0.80 / critical=0.90 / force_unload=0.95；审计 R3-BE7 同步）。

### 3.2 系统资源防护
- 内存 >85%：Celery 并发 4→1，暂停 LoRA 训练，清理 ChromaDB 缓存
- CPU >90%：暂停后台学习，浏览器标签数降至 ≤2
- 磁盘 IO >80%：延迟非关键写入；磁盘不足 → SYSTEM_DISK_FULL
- 学习引擎资源配额矩阵（空闲/创作中/推理中/断网/电池/低内存 6 场景）严格生效

### 3.3 应用安全（零信任）
- 绑定 127.0.0.1 唯一网卡；CORS 仅本地源；100 req/min 限流
- `/system/project/import` 等文件路径入参：白名单根目录 + `Path.resolve()` 穿越校验（修 BK-028）
- 密钥（keys/）不入库、不出网；日志敏感字段脱敏（已有 SensitiveDataFilter 保持）
- 浏览器沙箱：协议白名单(http/https) + 域名黑白名单 + 会话隔离（Cookie/缓存清理）
- 模型文件：SHA256 校验；LoRA 训练数据仅存本地；禁止未授权模型外传

## 5. 风险登记
1. 契约迁移波及面广 → ok()/error() 与 api.ts 双集中收口，调用点零改动（已验证 12 模块全走 helper）
2. 运行时 3.10 与文档 3.12 偏差 → 登记过渡，禁用过新语法（mypy 按 3.10 目标）
3. 大模型真机推理依赖 GPU/模型就位 → 验证以"模型缺失时诚实报错 + 小型冒烟"为通过线
4. 文档 392GB 模型清单无法实机核对 → 按"索引构建 + SHA256 校验链路"验收
