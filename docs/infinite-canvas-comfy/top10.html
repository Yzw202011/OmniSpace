四个梯队 · 怎么用

梯队项目对 OmniSpace 的用法
A · 立即用krita-ai-diffusion装 Krita + 插件直连 ComfyUI 8189，作为关键帧画布级精修工具（局部重绘/扩图画布/区域提示）。GPL 只约束分发，内部使用无碍。
B · 摘代码tigerowo + comfyui-ai-studio两个都是 MIT：前者摘导演台/摄像机参数/系列工作流的产品设计与 Zustand 组织；后者整段搬React Flow 画布骨架 + ComfyUI WS 重连对账 + workflow 自省器。
C · 学设计hero8152 + InvokeAI + mirainyahero8152 学「工作流封装成画布节点 + 循环批量」的产品形态（注意许可非标）；InvokeAI 学画布交互细节（Apache 可摘前端）；mirainya 学九宫格切图节点与插件热加载（无许可，只看不摘）。
D · 考古位其余（JasonS09 / kreonxv / Canvas-AI / sd-infinity）JasonS09 = 最小 inpaint 参考（MIT）；kreonxv = ComfyUI 站内画布思路；sd-infinity = 分块推理算法考古。均不投入主力时间。
给 OmniSpace 的三步建议（按当前架构零冲突排序） ① 本周可做：装 Krita + krita-ai-diffusion 指向 8189——精修痛点立即缓解，不动任何代码。
② 短名单：漫剧工作台若加「画布模式」，以 comfyui-ai-studio 为骨架（同栈 MIT）+ tigerowo 的导演台/系列工作流交互为蓝本，React Flow 起步——与现有 React 19 + Zustand 前端完全同构。
③ 远期：hero8152 的「workflow_api.json → 画布节点」模式是把咱们 31 份工作流资产产品化的终局形态；实施前先向作者确认许可（或只用其交互模式自己实现）。
