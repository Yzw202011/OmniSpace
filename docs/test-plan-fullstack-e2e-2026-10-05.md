# OmniSpace 全栈「仿真人操作 × 链路监控」测试计划 v1

> 制定：2026-10-05。依据：2026-09~10 连环实弹沉淀（激活门页/MagicAI 云链/sora_video/绑定显示根修/realportrait 风格包/漫剧六令连修线）+ 三张 UI 截图（漫剧工作区/漫画分格/MagicAI 页）+ 代码结构实测。
> 原则：**前端像真人一样点**（浏览器自动化，坐标点击+快照断言双轨）、**后端像哨兵一样盯**（API/DB/flow_trace/WS/GPU/RAM 六源取证）；每条带过关标准与量化指标；先便宜后昂贵；不带病进下一轮；发现并发会话在飞立即停手。

## 二、缺陷分级（沿用全项目口径）

- **P0**：崩溃/蓝屏/数据丢失/后端静默死亡/RAM 提交耗尽/僵尸进程/激活被绕过
- **P1**：主功能不可用（生成失败无出路、产物缺失、删除不生效、支付级=云端计费类误触发）
- **P2**：功能缺陷（假切换/进度失真/绑定显示丢/跨格串图/降级不诚实）
- **P3**：体验/文案/样式

## 三、硬性准入/准出

**准入（每轮开工前全过）**：
1. `git log -1` 记录基线 commit；前后端均为最新构建（前端 dist 时间戳 > 最后一次 src 改动）
2. 后端 `/health` 200 且 version/copy_id 记录入册；活动门：图像/视频队全空 + GPU 无 >1GB comfy + 近 5 分钟无他人任务
3. 测试数据隔离：专建 `TEST-E2E-` 前缀项目/会话/资产；用户真项目（微微一笑/逆天邪神等）**只读不动**
4. 每轮证据目录：`docs/测试记录/全栈E2E-2026-10-05/`（截图 PNG + curl 响应 JSON + 关键日志行 + DB 查询回执）

**准出（单轮判绿）**：本轮全部用例 ✅ 或 🔶（带证据与理由）；新发现 P0/P1 归零或挂账有主；六源证据齐备可复核。

**停手红线**：GPU 实弹撞并发任务；后端 RAM>28GB 或 GPU 温度>87°C；发现另一会话正编辑测试涉及文件（git status 骤变+py_compile 中间态）→ 暂停本轮，协调后再续。

## 二十、执行顺序与调度

1. **轮次依赖**：S→N→（D/W 并行）→（C/M/P 串行，GPU 活动门逐轮过）→MM→MA→SET→BE→Q→ST→V→PERF；每轮准入见 §三。
2. **成本阶梯**：先零成本（DOM/快照/API 只读）→低成本（本地小图/短对话）→高成本（关键帧/视频/超分）；视频/超分每轮 ≤3 发。
3. **GPU 专窗纪律**：C/M/P/ST-02/03 每用例前 `nvidia-smi`+队列探活；撞并发立即挂起本轮并记录。
4. **凭证纪律**：云 Key 只存测试环境变量；测试产物落 TEST- 前缀；结束时清理测试项目+还原全部设置。
