## 一、总纲

### 1.1 测试目的（五问五答）
1. **功能跑通吗？**——11 个导航模块每一条用户路径（点击/输入/上传/导出/删除）端到端可走通；
2. **前后端一致吗？**——前端显示的成功/失败与后端 DB、日志、磁盘、队列真实状态一一对应，假成功/假失败/静默吞错 = 一票否决；
3. **稳吗？**——长跑、重启、断网、资源压力、并发洪峰下不崩、不丢数据、能自愈；
4. **有洞吗？**——注入/穿越/越权/上传闸门/许可对抗等漏洞面主动攻击验证；
5. **好用吗？**——操作流程符合「未加载→自动加载」「失败带出路」「危险操作必确认」三条产品铁律，性能在 KPI 基线内。

### 1.2 严格度分级
| 级别 | 含义 | 执行要求 |
|---|---|---|
| **P0 阻断级** | 坏了软件不可用/资损/数据丢失/安全失守 | 每轮必跑，任一失败=本轮判废 |
| **P1 严重级** | 核心功能受损或误导用户 | 每版必跑，失败须修复或挂账 |
| **P2 完整级** | 边角/体验/性能精调/监控加固 | 发版前全量跑一遍 |

### 1.3 判定符号（诚实取证铁律）
- ✅ 通过：步骤全走完且全部预期成立，有取证（五源至少一源）；
- 🔶 有条件通过：主路径成立但命中「已知缺口对照表」编号（必须注明 K-xx）；
- ⚠️ 未测/证据不足：不得替用户宣称通过；
- ❌ 失败：任一预期不成立，附取证与初判根因，记录进本轮报告。

## 三、双轴方法论

### 3.1 前端轴 = 仿真人点击（browser-use IAB）
| 手段 | 用途与铁律 |
|---|---|
| domSnapshot | 一切定位的先行动作，禁盲坐标起步 |
| role/text 正则定位 | 复合可访问名（如「生成未完成分格（3）」）用唯一子串正则，**count==1 才许点** |
| fill + 失焦 | 受控组件一律 fill，onBlur 保存类控件必须 blur 后再断言（不失焦=没保存） |
| 点击必断言 | 重渲染窗口期点击会静默无效（资产 dock 实战坑），每次点击必须断言效果 |
| 截图旁证 | 布局断言以 DOM 量测为准，截图仅旁证；**截图超时立即改 DOM 断言**（历史坑） |
| CUA 坐标兜底 | role-click 超时的最后手段（学习页 G1 教训） |
| 人类节律 | 连续操作间隔 300~800ms 随机，暴露防抖/竞态类缺陷 |

### 3.2 后端轴 = 链路监控五源 + 实时监控点
**五源（评测只信这五源）**：
1. 真 Bash：python requests 优先（Git Bash curl 中文 body 必炸）；2. DB 只读查询（SQLite 三库）；3. 日志（logs/backend.log 含轮转件、启动页 HUD、ComfyUI 重定向件）；4. 磁盘（产物路径/大小/mtime/SHA256）；5. git diff（测试前后工作区对照，防误改防混淆）。

**实时监控点**：
| 监控点 | 采集方式 | 节奏 |
|---|---|---|
| 后端健康 | GET /health + backend.log 尾随 | 30s |
| GPU/显存/温度 | pynvml 脚本（回环白名单内） | 10s（重载期 2s） |
| RAM 提交余量 | psutil.commit | 10s（<4GB 告警，<2GB 熔断） |
| 任务队列 | image/video/novel/training 队列快照 + 前端任务条/铃铛（15s 轮询） | 事件驱动+30s |
| WS 帧 | /ws 消息中枢、/hardware/realtime(2s)、/learn/session/progress 抓帧 | 连续 |
| 状态栏一致性 | BottomStatusBar 与 hardware WS 对账 | 每组收尾一次 |
| flow_trace.db | flow_executions/flow_nodes 行数与状态 | 每用例前后各一次 |

## 四、仿真人操作纪律（违者该用例判无效）

1. **先 snapshot 后动手**；定位唯一（count==1）才许点。
2. **受控组件 fill 后必须失焦再断言**。
3. **每次点击必须断言效果**，「点了就算」= 无效执行。
4. **视觉结论 DOM 量测 + 截图双证**；截图超时改 DOM 断言，不重试截图。
5. **人类节律** 300~800ms 随机间隔；危险按钮（删除/清空/重置）加 1~3s 停顿模拟犹豫。
6. **不碰真实用户数据**：🔒 项目只读；一切写入用 `TESTAUTO-` 前缀。
7. **GPU 纪律（§16.6）**：任何 GPU 用例开跑前查后端实时任务（近 5 分钟提交+>1GB comfy 进程）；发现并发会话在飞立即停手，**绝不重启/杀 5800**。
8. **烧钱用例标 💰**（云端真实计费）：逐单先拍板再跑。
9. **失败不停手**：单条失败记录后继续（触发熔断除外）。
10. **定宽按钮坑**：删除/确认类按钮若布局位移（学习页 88px 定宽坑），二次点击前必须重 snapshot 重新定位。
11. **进度条不回退**：任何生成类用例观测进度单调性，回退即记录（假象或真 bug 均要留证）。
12. **错误必须有出路**：每个失败态断言「显错文案 + 重试/出路入口」双要素（产品铁律：真失败带出路）。

### 熔断纪律（触发即停整轮）
- RAM 提交余量 < 2GB（WER RADAR_PRE_LEAK_64 静默死亡线）；
- GPU 温度 ≥ 90°C 持续 2 分钟；
- 后端 /health 连续 3 次超时（静默死亡嫌疑）→ 取证后走**正规退出链**（启动页 5850 POST /api/quit；5800 /api/quit 是假货回 200 不退出）；
- 发现并发会话在飞任务 → 停手记录，等窗口。
