## 二、缺陷清单（本轮核心产出）

### 🔴 P1（阻断级候选）

**BUG-05｜恢复安排无取消通道（误触=定时炸弹）**
- 复现：POST `/system/restore` 安排后，UI/API **无任何撤销入口**，标记 `data/omnispace.restore-pending.{db,json}` 直至下次重启前一直生效，届时整库回滚到备份时点。
- 实弹险情：本轮 P-01 对照组误用真实备份文件名（`omnispace_20261018_213351.db`）→ 恢复被真实安排 → **测试侧手工删除标记文件拆除，pending_restore=False，零损害**。事件已按诚实取证铁律记录（evidence/baseline.json 同目录本报告 §四）。
- 修复建议：`POST /system/restore/cancel`（删标记+删暂存）+ UI 在「待恢复」徽标旁加「撤销安排」钮。
- 关联：H-07/08/09/13 的 UI 流转 ⏸ 窗口批。

**BUG-06｜项目导出全链瘫痪 + 错误文案撒谎**
- 根因：`src/api/system.py:1252` `_collect_project_bundle` 误用 `return ok({...})` 返回 **HTTP 信封**而非裸字典；`_write_project_archive:1273` 取 `bundle["project"]` → `KeyError: 'project'`。
- 影响：**任何类型项目（comic/manga）导出 100% 失败**；错误码谎报 `SYSTEM_BACKUP_FAILED「请检查磁盘空间」`（实际是代码 bug，违反降级诚实铁律）。
- 证据：backend.log 03:48/03:50/03:56 三次同栈；新旧进程同炸（排除老进程变量）。
- 波及：I-01/02/06/07/12 ❌，I-05/08 ⏸，P-22/P-23 ⚠️（阻断）。
- 修复建议：`_collect_project_bundle` 去掉 `ok()` 包裹直接 `return {...}`；catch 分支按真实异常给错误码。
