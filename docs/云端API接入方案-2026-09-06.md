## 1. 一句话结论

给软件建一套「云端外援」体系：用户在设置页粘贴**自己的** API Key（服务商直连，软件不经手、不中转、不抽成），然后把功能里的每个「AI 工位」（写剧本的、画图的、做视频的…）按需切到云端模型。漫剧创作 = 三个工位（文本/图片/视频）各绑一家，一次配置全链云端跑，**本地显卡全程空闲**——这正是 16G 卡跑不动高级视频模型的解法。

## 2. 背景与目标

1. **产品策略吻合**：买断制、内置成本归零已拍板（打包发行方案）；联网搜索已定「博查降为用户自带 Key」。云端 API 接入是同一策略的自然延伸——用户自付用量费，软件零成本解锁旗舰模型。
2. **硬件天花板**：本机 RTX 5070 Ti 16G（实际空闲 ~13.4G），本地装不下的模型（高级视频生成、超大文本模型）云端一条 Key 解决。
3. **并行收益**：云端调用不占本地显存，漫剧全链云端化后，绘画/训练可与漫剧**同时**进行（现有四锁互斥对云端作业豁免，见 §6.4）。

## 4. 核心设计：三层抽象

### 4.1 第一层：服务商连接（Provider）

用户在设置页添加的「一条连接」。数据结构（存 KV `cloud.providers`，JSON 数组）：

```json
{
  "id": "prov_a1b2",
  "name": "DeepSeek",
  "protocol": "openai_text",
  "base_url": "https://api.deepseek.com",
  "api_key": "sk-...",
  "models": ["deepseek-chat", "deepseek-reasoner"],
  "enabled": true,
  "extra": { "concurrence": 2 }
}
```

- **protocol（协议）四类**，见 §5；
- **内置服务商档案**：常用厂商预置好 base_url/协议/模型名单，用户只需粘贴 Key（可拉取模型列表的自动拉，拉不了的留手填框）；「自定义 OpenAI 兼容」作为万能兜底；
- 增删改、启停、连通性测试都在设置页完成，保存即时生效（与现有远程对话卡片同模式，无需重启后端）。

### 4.2 第二层：工位槽位（Slot）

功能里一个具体的「AI 工种」= 一个槽位。槽位注册表（后端单源，常量）：

| 槽位 | 说明 | 默认 |
|---|---|---|
| `dialog.text` | 对话页/通用写作文本 | 本地引擎 |
| `manga.text` | 漫剧剧本与 AI 切分 | 本地引擎 |
| `novel.text` | 小说创作 | 本地引擎 |
| `paint.image` | 绘画页出图 | 本地引擎 |
| `keyframe.image` | 漫剧关键帧 | 本地引擎 |
| `asset.image` | 角色资产图/四视图 | 本地引擎 |
| `comic.image` | 漫画成稿 | 本地引擎 |
| `manga.video` | 镜头视频 | 本地引擎 |

绑定关系存 KV `cloud.bindings`：`{"manga.text": {"provider_id": "prov_a1b2", "model": "deepseek-chat"}}`。**未绑定的槽位走本地引擎，行为与今天逐比特一致**（安全网铁律）。

槽位粒度刻意克制：文本按「功能模块」分（对话/漫剧/小说各自可不同模型），图片按模块分到绘画/关键帧/资产/漫画，视频只有一个。不做更细的逐端点绑定——配置面越大脑用户越懵。

### 4.3 第三层：运行时路由

每次生成任务的路由裁决：

```
槽位有云端绑定且 Provider enabled → 走云端适配器
否则                              → 本地引擎（现状不动）
```

云端调用失败的处理（对齐「未加载必须全自动」铁律）：
- **可自动恢复**（429 限流/网络抖动/5xx）：指数退避自动重试（默认 2 次），用户无感；
- **真失败**（401 Key 无效 / 402 欠费 / 内容审核拒绝）：报错**必带出路**——错误信息含服务商原话 + 两个按钮「去设置检查」「切回本地引擎」。不静默回退本地（避免悄悄烧本地 GPU + 风格断裂），但一键可切。

## 5. 三类协议适配器

### 5.1 文本：`openai_text`（批 1）

- POST `{base}/v1/chat/completions`，SSE 流式透传——**直接复用 `remote_backend.py` 的实现**，只是把「读单份 remote_dialog 配置」改成「按槽位绑定读 Provider」；
- 模型列表：支持的服务商拉 `/v1/models`，否则手填；
- 消费方：对话页、漫剧文本、小说、知识问答自动受益（都走 `dialog_engine`）。

### 5.2 图片：`openai_image` + `task_image`（批 2）

- `openai_image`：POST `/v1/images/generations`（OpenAI 兼容同步出图；硅基流动、Recraft、gpt-image 等走此协议）；
- `task_image`：**异步任务三段式**=提交（返回 task_id）→ 轮询（间隔 3~10s 可配）→ 取结果 URL 下载到本地 `data/`。通义万相、即梦属于此形状；
- 响应统一归一为 `{image_path, width, height}` 喂给现有下游（关键帧一致性链、资产入库零改动）；
- 图生图场景（参考图锚）：请求体带参考图（base64/URL 由适配器负责编码），各家的参考图参数差异封死在适配器内。

### 5.3 视频：`task_video`（批 3）

- 几乎全部主流云视频（可灵、即梦、万相视频、海螺）都是异步任务型，协议同 §5.2 三段式，差异只在请求体模板与轮询参数；
- 输入=关键帧图（本地生成或云端生成的文件上传/转 URL）+ 提示词 + 时长/画幅参数；
- 轮询上限默认 30 分钟，期间可取消（对齐 video_queue 取消语义），超时=真失败带出路；
- 产出视频落本地 `data/`，后续合成链零改动。

## 6. 关键机制

### 6.1 存储：独立 KV 键，不塞 system.settings 大 JSON

- `cloud.providers`（数组）与 `cloud.bindings`（对象）两个独立 KV 键，配独立 REST 端点（`/api/v1/cloud/providers`、`/api/v1/cloud/bindings` CRUD）——避免设置页整体 PUT 覆盖打架；
- schema 零迁移（system_settings KV 万能），数据库不动。

### 6.2 Key 安全

- Key 仅存本机 SQLite，出网目标=对应服务商官方域名，**软件不经手中转**（打包发行链零影响）；
- 后端 GET 一律打码（`sk-***abcd`，只回显末 4 位）；编辑时不回显完整 Key，留空=保持原值；
- 日志零 Key（沿用远程后端的日志纪律）；错误信息透出服务商业务信息但不透 Key。

### 6.3 队列分道：本地道 / 云端道

现状 `image_queue`、`video_queue` 均为单 worker 且持本地功能锁。改造：

- 任务按路由结果进**两条道**：本地道=现状（单 worker+持锁，逐比特不变）；云端道=独立 worker、并发上限可配（默认 2，防触发服务商限流）；
- 排队/取消/「排队中·前N」UI 不变，用户看到的仍是同一条队列快照（快照合并两条道）。

### 6.4 互斥豁免（本方案最大产品收益）

- 走云端的槽位**不 acquire** `dialog/paint/video_gen` 本地锁、不占显存（remote 伪域语义推广）；
- 效果：漫剧全链云端化时，用户可以同时本地绘画/训练——16G 卡的「独木桥」变「立交桥」；
- 改动点收敛在各链入口的锁申请处（先判路由再拿锁），`feature_lock` 本体不动。

### 6.5 与现有「远程推理服务器」的归一

- 现有 `remote_dialog_*` 配置 = 本体系的一个特例（`protocol=openai_text` 的单 Provider）；
- 批 1 落地时自动迁移：检测到旧配置→生成一条同名 Provider（Key/地址/模型带过去，enabled 继承），旧键保留不删（回退安全）但 UI 不再单列；
- 设置页「远程推理服务器」卡片升级为「云端 API 服务」卡片（Provider 列表：增删改测/启停/每个 Provider 显示打码 Key 与模型）。

### 6.6 模型选择 UI：云端模型混入现有下拉

- 各功能页现有「模型」下拉尾部拼接「云端」段（`云端 · DeepSeek · deepseek-chat`），选中即把该槽位绑到云端模型；选回本地模型=解绑；
- 漫剧项目内提供「AI 接入」区块：三个工位（文本/图片/视频）各一个下拉 + 「全部切换为云端/全部恢复本地」快捷键；
- 下拉数据=后端聚合端点返回（本地模型 + 各 enabled Provider 的模型），前端不感知协议细节。

## 7. 「漫剧三 API」全链示例（用户场景走查）

配置一次性动作（≈3 分钟）：
1. 设置 → 云端 API 服务 → 添加「DeepSeek」（粘贴 Key，测试通过）；
2. 添加「通义万相」（粘贴 Key，测试通过）；添加「可灵」（粘贴 Key，测试通过）；
3. 进漫剧项目 → AI 接入 → 剧本文本=DeepSeek / 关键帧图片=万相 / 镜头视频=可灵（或点「全部切换为云端」）。

日常生成：
4. AI 切分 10 镜 → 走 DeepSeek（SSE 流式照常显示）；
5. 资产图/关键帧 → 入图像队列云端道，万相出图，自动落本地链路下游；
6. 镜头视频 → 入视频队列云端道，可灵出片，轮询期间可取消；
7. 全程本地显卡 0 占用——此刻开绘画页照样出图。

异常路径：
8. 可灵返回余额不足 → 该镜头任务失败态，错误=「可灵 API：账户余额不足（402）」+ 按钮「去设置检查」「切回本地引擎」；其余已出图的资产不丢。

## 11. 风险与边界

1. **各家内容审核差异**：云 API 会拒部分题材（本地模型不会），属服务商政策，报错透传原话带出路；
2. **隐私边界**：图生视频/图生图需把本地生成的图片上传给服务商——Provider 档案与漫剧 AI 接入区块各放一行提示；
3. **费用感知**：软件不显示金额（无价目表依赖），视频类在确认弹窗提示「该服务按量计费」；账单看服务商后台；
4. **协议漂移**：云厂商改版=适配器跟进（内置档案可热更的余地留到批 4 再议，MVP 随版本发）；
5. **单卡行为铁律**：所有本地路径逐比特不变，云端=纯增量分支；批 1~3 各带哨兵单测锁「未绑定=旧行为」。

## 12. 三个「暂走本地」功能的云端化方案（2026-09-06 补，批2 遗留边界收口）

批2 交付时三个功能仍走本地引擎：角色四视图、资产「重生」入口、绘画页局部重绘（蒙版）。代码级调研后的结论修正了批2 时的保守判断：

### 12.1 依赖真相（调研结论）

| 功能 | 批2 时判断 | 代码级真相 |
|---|---|---|
| VL 校验（视角组合/图文符合度） | 「本地 VLM 穿不进去」 | **误判**：都走 get_dialog_engine()（comic_gen.py:271/376/447）——对话工位绑云端后校验**自动云化**，零额外工作 |
| SAM 白底漂白 | 同上 | 属**后处理**：对已落盘的生成结果抠图，与生成通道无关；SAM 按需装载（2.5GB）用完即卸，保留本地无碍 |
| 四视图生成/错格修复 | 同上 | 真依赖：onepass 整图 engine.generate（纯文生图，**可云**）；_repair_view_cell 错格局部修复用绘画引擎（云端无对应能力，需降级策略） |
| 资产「重生」 | 同上 | _regenerate_asset_sync 普通资产分支与 _generate_asset_sync 同构（**同一招可云**）；四视图分支随四视图方案 |
| 局部重绘 inpaint | 同上 | 真依赖：engine.inpaint(图, 蒙版)；云端各家能力碎片化（OpenAI edits 专有；DashScope 无通用 inpaint） |

### 12.2 方案

**A. 角色四视图 → 云端（成本低，建议批4 实施）**
- 生成段：onepass 提示词协议照用，engine.generate 换 cloud_image_client（文生图直送，2x2 整图）；
- 错格修复：云端模式降级为**整图重 roll**（云端再生成一次，放弃逐格修复——逐格修复本就是抽卡补救，整图重抽语义等价）；
- VL 校验/SAM 漂白：照旧（校验自动跟随对话工位的云端绑定；SAM 本地后处理保留）；
- meta.engine 标注 cloud。

**B. 资产「重生」→ 云端（成本最低，建议批4 与 A 同批）**
- 普通资产：_regenerate_asset_sync 加 cloud_endpoint 参数，生成段分支同 _generate_asset_sync 路径⓪；
- 四视图资产：随 A 方案管线。

**C. 局部重绘 → 分档（成本高，建议批4 只做第①档）**
- ①openai_image 协议扩展 /v1/images/edits（gpt-image-1 支持 image+mask 真 inpaint）——绑定该类连接时可用；
- ②task_image 走「蒙版合成+图生图」降级（蒙版区涂色标记连同原图传 qwen-image-edit 类模型）——质量不可控，须实弹验证后再定是否开放；
- ③不支持时如实报错（现状），错误信息按连接类型给出路。

### 12.3 拍板点
- A/B 建议批4 实施（约 1 天，复用批2 适配器与队列，无新协议）；
- C ①档批4 实施，②档待实验；也可 C 整体缓一缓（局部重绘使用频率与云端收益待观察）。
