## 二、角色一致性相关机制清单

### 2.1 已实现机制

#### 机制 1：参考条件图（Reference Conditioning / 多资产拼图）

- **文件**：`backend/api/manga/keyframe.py`
- **函数**：`_load_row_reference(db, row)` — 第 597 行
- **原理**：将 character / scene / prop 三类资产图合成一张横向拼图，作为 FLUX.2 Klein 的 `image` 参数传入。FLUX.2 的 img2img 接口把参考图视觉 token 拼入序列，等价于多图参考注入（类似 IP-Adapter 的多参考机制），且零引擎改动。
- **拼图规则**：
  - 顺序：character → scene → prop
  - 统一高度：640px
  - 白底间隔：24px
  - 最大张数：6 张
- **特殊处理（V33 人脸事故修复）**：character 四视图横排（宽≥2000 且 1.6≤宽/高≤2.0）时只取第 1 格（front 全身立绘），提升面部 token 占比。

#### 机制 2：面部参考图（特写镜专用）

- **文件**：`backend/api/manga/keyframe.py`
- **函数**：`_load_face_reference(db, row)` — 第 665 行
- **目的**：ECU（极端特写）/ MCU（中近景）镜的面部细节引导
- **来源优先级**：
  1. `character_face.png`（写实向工作流 qwen-image 产物）
  2. `portrait_views/closeup.png`（四视图独立落盘）
  3. `portrait.png` 四视图横排裁右格（closeup 视图）
- **背景**：V32 人脸一致性事故——特写格无面部参考时回退全身拼图，klein 写实先验 + 质量块写实词把脸推向真人化（削瘦+毛孔+无腮红）

#### 机制 3：角色文本锚（Character Text Anchor）

- **文件**：`backend/api/manga/keyframe.py`
- **函数**：`_shot_image_prompt_from_abc()` — 第 278 行（`char_prompt` 参数）
- **注入格式**：
  ```
  同一角色（各镜严格一致，画面中始终只有这一个女孩，
  除她以外不得出现任何人物）：{char_prompt}。
  ```
- **空描述词兜底**（V31 事故修复）：上传型资产 prompt 为空时，使用「资产名 + 外貌与角色设定图严格一致」弱锚
- **唯一性限定**（v26 事故修复）：显式声明单人单物场景，防止参考 token 被理解为多实例

#### 机制 4：C 段角色外貌词剥除

- **文件**：`backend/api/manga/keyframe.py`
- **函数**：`_strip_char_appearance(body, char_prompt)` — 第 257 行
- **剥除模式**：发型（马尾辫等）、上衣（衬衫/T恤等）
- **原因**：v20/v21 发型漂移根因是三层拔河——资产图 vs 资产 prompt vs C 段正文。必须物理剥除冲突文本。

#### 机制 5：构图指令层身份锚定（ECU/MCU 镜）

- **文件**：`backend/api/manga/keyframe.py`
- **位置**：`_SHOT_FRAMING` 字典 — 第 192 行
- **ECU 镜指令**：
  ```
  Extreme close-up, one single face fills the entire frame,
  identical hairstyle, facial identity, eye color and skin tone
  as the reference character, ...
  ```
- **MCU 镜指令**（V35 增强）：
  ```
  Medium close-up, ..., identical facial identity, hairstyle
  and skin tone as the reference character
  ```
- **原理**：把发型/面部身份/瞳色/肤色从 char 锚中段提升到构图指令层（最高遵循权重），与参考条件图双通道锁定。

#### 机制 6：冲突词物理剥除（V32/V35 人脸事故）

- **位置**：`_shot_image_prompt_from_abc()` 第 345-361 行、第 410-419 行
- **剥除内容**：
  - ECU 构图指令中的写实强制词（realistic facial proportions, fine pores, no blush makeup, matte skin finish）
  - 风格质量块中的外貌强制词（visible pores, without makeup or blush）
- **原因**：写实质量词与 char 锚「与设定图严格一致」自相矛盾——有 char 锚时外貌管辖权全交资产锚+参考条件图。

#### 机制 7：后处理档位资产仲裁

- **文件**：`backend/api/manga/keyframe.py`
- **位置**：`_generate_keyframe_sync()` 第 772-782 行
- **规则**：character 资产 meta.model 含 "klein-4b" → 强制 stylized 档
- **原因**：V32 人脸事故——立绘资产的粉腮红/光滑肤/饱满苹果肌是设定一部分，realistic 档后处理（红晕抑制+皮肤微纹理+饱和度压降）会反向消解这些特征。

#### 机制 8：同 Seed 四视图一致性（资产生成阶段）

- **文件**：`backend/api/manga/comic_gen.py`
- **函数**：`_generate_four_views()` — legacy 逐视图路径
- **机制**：四张视图（正面/侧面/背面/特写）使用同一个 seed 生成
- **一致性评分**：`_views_consistency(view_imgs)` 计算跨视图一致性分数

## 四、A/B/C 描述协议中角色/场景一致性字段设计

### 4.1 协议结构总览

```
A. 全局风格：{项目画风}，{固定视频质感token}。整体氛围为{氛围句}。全程无字幕、无背景音乐、只有音效。

B. 高密度世界观构建：{角色外貌}、{场景环境}、{时间天气}、{道具}、{角色情绪基准态}。

C. 分镜时间轴（分镜网格 N×N）：
[0.0s-0.1s] 画面：参考图保持 | 运镜：固定 | 音效：无
[起始s-结束s] 画面：[标题] {画面内容（含景别与主体动作）} | 运镜：{英文运镜术语} | 音效：{环境音与动作音}
...
```

### 4.2 与角色一致性相关的设计

| 字段/位置 | 设计意图 | 约束规则 |
|-----------|---------|---------|
| B 段角色外貌描述 | 世界观层角色锚定 | 必须严格沿用绑定资产设定，不得改动发型/发色/服装/体型 |
| 用外貌特征指代角色 | 避免人名干扰 | 不要使用人名，只用外貌特征指代 |
| 资产设定注入 prompt | LLM 生成时已知资产 | 绑定资产 prompt 全文注入，LLM 须严格遵循 |
| 资产规则声明 | 硬约束 | "外貌与场景一律以绑定资产设定为唯一事实来源，B 段与 C 段不得偏离" |
| 绑定角色必出场规则 | 防漏角色 | "绑定的角色资产必须在本镜出场（B 段写其外貌，C 段作为画面主体之一）" |

### 4.3 与场景一致性相关的设计

| 字段/位置 | 设计意图 | 约束规则 |
|-----------|---------|---------|
| B 段场景环境 | 世界观层场景锚定 | 场景环境、时间天气、道具描述 |
| 专名泛化规则 | 防止生图按字面拆解 | 地点/机构/街道等专名必须泛化为视觉描述（如"望云亭苑"→"现代沿海别墅小区"） |
| 场景资产 prompt 注入 | LLM 生成时已知场景 | 同角色资产一样注入 prompt |

### 5.3 FLUX img2img 的特殊语义

**文件**：`paint_engine.py:img2img()` — 第 1134-1138 行注释

- FLUX.2 Klein 的 `image` 参数是**参考条件图**，不是传统 img2img
- latent 从纯噪声起步，strength 不参与
- 输出尺寸跟随 params 的 width/height（不跟随参考图尺寸）
- 参考图内部缩至 ≤1MP 作条件 token

### 5.4 负向提示词

| 模型 | 负向提示 | 说明 |
|------|---------|------|
| FLUX.2 Klein | **无**（无 negative_prompt） | 负向语义由调用方写入正向禁令 |
| SDXL（降级） | `_STYLE_NEGATIVE` 或风格包 `negative_hint` | 标准 SDXL 负向提示 |
