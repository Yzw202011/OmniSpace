## 第一章 项目总览

### 1.1 项目定位

OmniSpace AI 是一款本地化AI创作工作站，集成AI对话、AI绘画、漫剧创作、知识学习、模型管理、视频风格化六大核心模块，通过五大智能引擎实现模型预测预加载、自主学习、LoRA微调、协同调度和硬件编码。

## 第三章 核心模块1：OmniChat（AI对话）

### 3.1 功能子模块清单

| 序号 | 功能名称 | 描述 |
|------|----------|------|
| 1 | 多模态对话 | 支持文本+图像输入，流式文本输出 |
| 2 | 剧本润色 | 基于影视行业知识库的专业润色 |
| 3 | 分镜描述生成 | 输入剧情自动生成结构化分镜描述 |
| 4 | Agent工具调用 | Function Calling协议，浏览器搜索/文件操作等 |
| 5 | 上下文记忆 | 多轮对话记忆，会话持久化 |
| 6 | RAG增强 | 对话前自动检索ChromaDB Top-5知识片段 |
| 7 | 被动补全 | 检测知识缺口时自动触发联网学习 |
| 8 | 流式输出 | SSE推送，打字机效果 |
| 9 | 语音交互 | TTS+ASR集成（Edge-TTS+FunASR） |
| 10 | 意图识别 | 简单问答/知识检索/工具调用三路分类 |

### 3.2 技术原理

| 技术项 | 规格 |
|--------|------|
| 推理模型 | Qwen3-VL-8B(复杂)/4B(常规)/2B(快速)，按GPU显存自动选择 |
| 推理后端 | vLLM |
| 上下文长度 | 最大8K tokens |
| 量化方案 | fp16/int8/int4动态切换 |
| 流式输出 | SSE (Server-Sent Events) |
| RAG检索 | 混合检索(FTS5 + HNSW)，RRF重排序，HyDE增强 |
| 向量化 | BGE-large-zh（1024维），过滤score<0.5 |
| 首字延迟 | <500ms(标准≤4K) / <800ms(8K满上下文) |

### 3.3 实现步骤（10步）

| 步骤 | 操作 | 技术实现 |
|------|------|----------|
| 1 | 用户输入捕获 | 前端HTTP POST `/api/v1/chat/stream` |
| 2 | 参数校验 | FastAPI路由层 + Pydantic v2 |
| 3 | RAG检索 | ChromaDB Top-5检索，<100ms |
| 4 | 向量查询 | BGE-large-zh向量化，过滤score<0.5 |
| 5 | 上下文组装 | System Prompt + 检索知识 + 历史对话 + 用户输入 |
| 6 | 模型选择 | 根据GPU显存自动选择8B/4B/2B |
| 7 | 流式推理 | PyTorch 2.8流式推理，yield token逐字输出 |
| 8 | 被动补全 | 检测不确定性标记→提取关键词→快速搜索→补充推理 |
| 9 | 历史记录 | 对话历史写入SQLite，触发行为学习记录(异步) |
| 10 | SSE返回 | 流式token推送至前端，打字机渲染 |

### 3.4 API路由

| 方法 | 端点 | 说明 |
|------|------|------|
| POST | `/api/v1/chat/stream` | 流式对话（SSE），支持多模态输入 |
| POST | `/api/v1/chat/complete` | 非流式对话，返回完整回复 |
| GET | `/api/v1/chat/history` | 获取对话历史列表（分页） |
| GET | `/api/v1/chat/history/{session_id}` | 获取指定会话完整对话记录 |
| DELETE | `/api/v1/chat/history/{session_id}` | 删除指定会话 |
| POST | `/api/v1/chat/context` | 添加上下文知识片段 |
| DELETE | `/api/v1/chat/context/{context_id}` | 移除上下文知识片段 |
| GET | `/api/v1/chat/models` | 获取可用对话模型列表 |
| GET | `/api/v1/chat/usage` | 获取对话使用统计（Token用量） |

## 第五章 核心模块3：OmniComic（漫剧创作）

### 5.2 技术原理

### 7.3 显存4级阈值策略

| 显存使用率 | 状态 | 精度降级 | 模型卸载 |
|-----------|------|----------|----------|
| <70% | 安全区 | 维持fp32/bf16 | 全量驻留 |
| 70%-85% | 警戒区 | 降级至fp16 | 保持全量，开启碎片整理 |
| 85%-95% | 危险区 | 降级至bf16/int8 | 卸载非活跃LoRA至内存 |
| >95% | 溢出区 | 强制int8量化 | 卸载基础模型，启用CPU Offload |

### 7.4 实现步骤

| 步骤 | 操作 | 技术实现 |
|------|------|----------|
| 1 | 模型加载请求 | 模块发起请求(模型ID+优先级+量化参数) |
| 2 | 显存检查 | 空闲显存>=所需显存→直接加载 |
| 3 | 显存不足处理 | 检查可卸载模型→卸载最低优先级→加载新模型 |
| 4 | 优先级抢占 | P0>P1>P2>P3>P4>P5 |
| 5 | 加载完成通知 | 更新模型状态并通知前端 |
| 6 | ML预测预加载 | XGBoost预测→概率>0.7→异步加载→用户切换即时可用 |

### 8.2 技术原理

| 技术项 | 规格 |
|--------|------|
| 微调引擎 | LTX-2 LoRA微调引擎 |
| 量化 | QLoRA 4bit量化 + 梯度检查点 |
| 编码器 | FFmpeg 7.x + AV1 (NVENC/SVT-AV1) |

## 第九章 五大智能引擎

### 9.1 LTX-2 LoRA微调引擎

| 项目 | 规格 |
|------|------|
| 原理 | 基于LTX-2 Diffusion Transformer的Low-Rank Adaptation微调 |
| 核心 | 冻结预训练权重，仅训练低秩分解矩阵(A和B) |
| 量化 | QLoRA 4bit量化 + 梯度检查点，24GB显存可训练720p LoRA |
| 实现库 | peft库 + bitsandbytes 4-bit量化 |
| v2.3.1加速 | Flash Attention-2 + 8bit AdamW，训练时间减少>30% |
| 触发条件 | 用户提交训练 / 数据>=100条自动触发 / 定时(每周) / 手动 |
| 训练参数 | Epochs=3, LR=2e-5, rank=16, alpha=32 |
| 优化器 | bitsandbytes AdamW 8-bit 或 PagedAdamW |
| 调度器 | cosine_with_restart 或 polynomial |
| 训练队列优先级 | P2（GPU 30% / CPU 50% / 内存 50%，同时仅1个训练任务） |
| 早停策略 | Validation Loss回升>5%→停止；Loss震荡→降LR(×0.8)；Loss停滞→增加Rank |
| 执行流程 | 数据预处理→基座模型加载→QLoRA量化→显存分配→梯度累积→训练循环→Checkpoint保存→质量评估→注册新版本 |

### 9.2 ML预加载预测引擎

| 项目 | 规格 |
|------|------|
| 原理 | XGBoost时序预测模型，基于历史操作序列预测下一模型 |
| 特征窗口 | 50步历史操作序列（v2.3.1从30步扩展到50步） |
| 特征工程 | 当前功能/操作时间(小时/分钟)/操作序列(最近10步)/历史切换模式/项目上下文 |
| 模型大小 | ~50MB，常驻内存 |
| 推理延迟 | <50ms |
| 准确率 | >85%（v2.3.1优化后） |
| 预加载阈值 | 概率>0.7→异步加载 |
| 缓存策略 | 预加载完成后更新缓存状态，用户切换时即时可用(0等待) |
| ML预测命中切换时间 | <500ms |
| 执行流程 | 用户操作事件流→特征提取→XGBoost推理→预测下一功能+概率→概率>0.7→触发预加载→检查GPU空闲显存→异步加载→用户切换即时可用 |

### 9.3 协同调度引擎

| 项目 | 规格 |
|------|------|
| 原理 | 强化学习(PPO)优化资源分配策略 |
| 状态空间 | GPU显存/CPU/内存/当前活跃功能/任务队列 |
| 动作空间 | 模型加载/卸载/精度调整/任务优先级调整 |
| 奖励函数 | 用户等待时间负奖励 + 资源利用率正奖励 + OOM大额负奖励 |
| 调度策略 | 6x6互斥矩阵 + P0-P5优先级抢占/卸载 |
| 资源冲突率 | <1% |
| 调度效率提升 | >20% |
| 资源监控频率 | GPU显存/利用率：每2秒；CPU/内存：每5秒；磁盘IO：每10秒 |

**优先级表**：

| 优先级 | 模型/模块 | 抢占策略 | 卸载策略 |
|--------|-----------|----------|----------|
| P0 | Qwen3-VL-8B(Agent模式) | 不可抢占 | 仅用户手动卸载 |
| P1 | FLUX.1-dev(生成中) | 可被P0抢占 | 保存中间状态后卸载 |
| P2 | LTX-2(视频生成中) | 可被P0/P1抢占 | 保存Checkpoint后卸载 |
| P3 | OmniLearn(训练中) | 可被P0-P2抢占 | 暂停训练，保存状态 |
| P4 | ControlNet/IP-Adapter | 随基座模型卸载 | 立即卸载 |
| P5 | MLPredict-XGBoost | 不可抢占 | 仅系统关闭时卸载 |

### 9.4 AV1硬件编码引擎

| 项目 | 规格 |
|------|------|
| 硬件加速 | NVENC(NVIDIA) / AMF(AMD) |
| 软编降级 | SVT-AV1 |
| 码率控制 | CRF 23 / VBR自适应 |
| 编码参数 | preset 6, keyint 240, AAC 256kbps |
| RTX 50系 | NVENC AV1硬编，>120fps |
| RTX 30/40系 | NVENC H.264/H.265硬编，>80fps |
| AMD RX 6000+ | SVT-AV1软编(多线程)，CPU<80% |
| 纯CPU | SVT-AV1软编(低速) |
| 降级策略 | AV1失败→自动降级至H.264，降低分辨率/码率 |
| 执行流程 | 导出请求→硬件探测→选择编码器→码率控制→帧级编码→封装→进度回调→完成通知 |

### 9.5 自主学习引擎

| 项目 | 规格 |
|------|------|
| 原理 | RAG(ChromaDB向量检索+BGE嵌入) + Agent决策树(ReAct模式) + 增量学习闭环 |
| 好奇心驱动 | PPL(Perplexity)驱动的好奇心探索 + 知识图谱覆盖率奖励 |
| 双层反哺 | RAG即时注入(毫秒级) + LoRA深度融入(分钟级) |
| 知识生命周期 | 青年期(<7天,高频,全量加载) → 成熟期(7-30天,正常,按需检索) → 沉淀期(30-90天,低频,LRU缓存) → 淘汰期(>90天,归档冷存储) |
| Agent终止条件 | 目标覆盖度>90% / 预算用尽 / 用户停止 / 资源被抢占 / 遇到障碍 / AI循环 / 单次>60分钟 |
| 量化指标 | 创作功能延迟增加<5%，知识提取>5个/页，检索延迟<100ms，召回率>90% |
| 知识处理管线 | 内容过滤→内容分段→知识提取(Qwen3-VL)→质量评估→SimHash去重→向量化入库(ChromaDB+FTS5+图数据库) |
