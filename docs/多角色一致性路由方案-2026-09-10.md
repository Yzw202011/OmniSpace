# 多角色 comfy+PuLID 一致性路由方案（2026-09-10，§16.1 四段制）

> **来源**：UAT 补充轮实弹——单角色分格一致性优秀（PuLID 硬锁命中），但
> chars=2 面板被路由条件 `len(char_assets)==1` 拦进 diffusers 无锁路线，
> 实测画风漂移+角色不符（日志铁证 keyframe.py:1204，图片四格均在案）。
> **用户令**：把多角色纳入 comfy+PuLID 多参考路由，出方案再动手。
> **拍板前不动任何代码。**

## 0. 大白话总览

**一句话：现在「一个角色」的格子有身份锁、画风稳；「两个角色」的格子被
分去一条没有锁的旧产线，画风人物全飘。方案=给双角色格子换上主力产线：
两张角色锚点图都喂进 FLUX.2 原生多参考级联（引擎现成能力，零引擎改动），
主角色再加 PuLID 面部硬锁；更进一步的「双人双 PuLID」先做一次 PoC 探路，
成了再上。**

## 0.1 现状证据（2026-09-10 实测）

- 路由条件：`keyframe.py:1201` `len(char_assets) == 1` 才走 comfy+PuLID；
  注释自述原因：「多角色行单 ID 通道会错锁身份」（单张身份图会把 A 的脸
  锁到 B 身上）——担心正确，但放任漂移是更差解。
- 引擎能力（comfy_paint_engine.py 实读）：
  - **N 图参考级联现成**：`ref_names` 列表 → N 个 ReferenceLatent 级联
    （:388-395，「FLUX.2 原生多参考语义」），逐图分辨率可控（D-2）；
  - **PuLID 链为单身份**：`pulid_image_name` 单图 → ApplyPuLIDFlux2
    （:335-353），双身份未验证；
  - 参考注入模式 `reflatent: off/auto/both`（PuLID 激活时参考图自动走
    off，身份走 attention 锁）——多角色场景需要改为 both（参考+锁并行）。
- 实测对照：chars=1 两格（comfy+PuLID）锚点全命中；chars=2 一格
  （diffusers 24 步文生图）画风漂移+角色不符+场景偏题。

## 一、改动清单（分两步，各自独立可回退）

**Step A（主力，预计解决 80% 问题，引擎零改动）**
1. `src/api/manga/keyframe.py`（路由 ~:1201）：
   条件 `len(char_assets) == 1` → `1 <= len(char_assets) <= 2`；
2. 同文件参考装配段（chars≤2 分支）：`ref_names` = 各绑定角色的
   portrait.png（每人一张锚点）；`pulid_image_name` = **主角色**（
   asset_ids 首位）的特写 face_ref；`reflatent` 强制 `both`（参考+身份
   并行，覆盖单角色时的 off 语义）；
3. 提示词装配：多角色时 prompt 显式写出各角色名与外貌锚（已有 v2 描述
   词含名字锚，复核拼接顺序）；
4. 新增哨兵单测：chars=2 → 断言走 comfy 路由 + ref_names 含两角色锚 +
   pulid 取首位；chars=3 仍走 diffusers（容量上限外不变）。

**Step B（PoC 探路，可选，1-2 次 GPU 实验）**
5. `comfy_paint_engine.py`：级联第二个 ApplyPuLIDFlux2（identity B），
   强度 A=1.0/B=0.8 起试；产出对照图交用户目验双身份是否兼立。
   → 成立则 Step A 的 pulid_image 扩为 per-character；不成立则维持
   A 方案（双身份靠多参考 + 提示词名字锚）。

## 二、影响面

- 影响面=漫画分格生成（comic 漫画页），**漫剧 H3 视频链与
  VIDEO_ROUTING_TABLE 完全不涉及**（冻结令无碰撞）；对话/绘画模块不动。
- chars=1 行为**不变**（条件对 1 的真值不变，纯扩 2）；chars≥3 维持
  diffusers（多参考稀释风险，容量外维持现状）。
- 预期改善：双角色格画风与单角色格统一（同 klein-4b+同风格包+同后处理
  档位），角色外貌经参考锚约束；**遗留风险**：双身份在无 PuLID-B 时
  依靠参考+名字锚，属「软锁」，B 相貌细节（眼镜款式等）可能轻微漂移。
- 参考图增多 → 单格显存/时长略增（1.0MP×2 参考级联，估 +10~20% 时长）。

## 三、验证方法（每步实弹）

- Step A 单测：哨兵 2 例（chars=2 路由断言/chars=3 不变断言）+ 既有
  keyframe 路由测试全绿 + ruff/mypy；
- **实弹验收（金标准）**：重生成 UAT 漫画测试0910 格 3（双角色同框）——
  ①画风与格 2/格 4 统一（线风日系，非吉卜力淡彩）；②林小满锚命中
  （黑发/红发卡/白衬衫蓝背带）；③陈默锚命中（黑框眼镜/深灰卫衣）；
  ④构图符合「走廊交谈+罗盘递向」。四条全中才算过；
- 回归：单角色格重生成一张，确认路由与产物不变。

## 四、风险与回退

- **双身份互相稀释**（A 的脸带 B 的眼镜之类）：Step A 用「参考+名字锚」
  软锁，可能不完美——如实交付对比图，由用户判定是否需要 Step B；
- ** PuLID 双链未知数**（Step B）：PoC 失败即弃，不影响 Step A；
- 回退：路由条件单行还原 + env 开关 `OMNI_KEYFRAME_PULID_AUTO=0`
  （既有一键回退）；改动集中单文件，git revert 即净。
- 估时：Step A 半天（含实弹）；Step B PoC 半天（估时≠承诺）。
