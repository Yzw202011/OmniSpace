## 0. 可行性评估（全家桶模式，诚实结论）

**结论：能做，工程上没有拦路虎；但全家桶把风险从"分发体验"转移到了"介质、库存与法律"三处。** 体积事实（2026-09-02 实测，硬链去重）：

| 项 | 实测体积 |
|---|---|
| models/（09-02 清理后） | 244G |
| ComfyUI 侧权重（去重独有部分） | 21G |
| 程序体（make_dist 白名单包） | 6.5G |
| **全家桶（全镜像）** | **≈272G** |
| 全家桶（精编版，砍备胎，见 D5） | ≈150~180G |

### 0.1 全家桶模式的得与失（诚实两边都说）

**得**：
- 免下载器开发（省 3~4 天），用户**零网络依赖、零等待、零下载失败**——离线交付完全闭环；
- 不存在档位选择困惑，交付物只有一个；
- 对买断制 + 小规模线下交易（寄硬盘/到店拷贝/熟人盘对盘），这是**合理甚至优选**的形态。

**失（不粉饰）**：
1. **盗版防线全部压在激活锁上**：拷贝即完整产品（模型是明文 safetensors，公开可验证）。原下载器模式至少控制模型分发渠道；现在唯一防线 = license_gate 激活锁 + watermark 客户水印（泄露溯源）；
2. **模型再分发的许可证风险 = 高危** ⚠️⚠️：全家桶卖给用户 = 把 FLUX.2-klein（非商用许可）、MiniMax-H3（商用敏感）、Qwen/Wan/LTX 等全部权重**商业再分发**。这条法律线从未审计过，是全家桶模式最大的隐性风险，**不是技术问题**；
3. **库存硬约束**：开发机 E 盘剩 140G、D 盘剩 109G——**都放不下第二份 272G 全家桶**。装配线输出必须直写外接盘（≥300G）；
4. 交付介质现实：移动硬盘 USB3 拷贝 272G ≈ 25~50 分钟（精编 150G ≈ 15~25 分钟）✅ 可行；网盘非会员限速下载 272G 以天计 ❌ 基本不可行；
5. 不分档的代价：8G/12G 显卡用户背着永远加载不了的 H3 42.7G / klein-9b 等死重；运行时仍按硬件自动降级路由（保证小卡用户能用，但磁盘白占）；
6. 模型更新 = 重发整包（程序更新可只换程序体目录——models/ 独立分目录，结构已支持 ✅）。

### 0.2 六维可行性打分（全家桶口径）

| 维度 | 评级 | 依据 |
|---|---|---|
| 技术架构 | ✅ 高 | 09-01 干净机装机实测过（DLL 事故已沉淀哨兵）；boot 链不依赖模型存在，先程序后模型 |
| 打包基建 | ✅ 高 | make_dist 白名单 + 哈希清单 + 金母版已建成；需增 `--bundle` 模式装模型（S6'） |
| 模型路由 | ✅ 高 | manifest v3（20 项实测登记）现成；运行时按硬件降级保留 |
| 桌面壳 | ✅ 可行 | boot.py 生命周期机器全复用（§2），壳本身 2 周 |
| 介质与库存 | ⚠️ | E/D 盘放不下第二份全镜像；水印签名 270G 全量 HMAC 耗时未实测（估 15~30 分钟/份） |
| 分发合规 | ⚠️⚠️ | 模型商业再分发许可零审计（klein/H3 为高危项）——**商用前必须过，卡发行不卡开发** |
| 稳定性 | ⚠️ **最大技术风险** | 后端静默死亡根因未闭合、24h 压测未做。小白对"无声死"零容忍，生死线不变 |

**总评：全家桶模式工程可行性依然高（比下载器模式还少 4 天开发）；成败变量 = ①稳定性收口 ②激活锁+水印这条唯一防盗线做扎实 ③模型许可证审计。**

## 1. 定位

**目标**：把「launcher + 系统浏览器」封装成**双击即用的桌面 App**；交付物 = **一个全家桶目录**（程序体 + 全部模型，≈272G 或精编 ≈150~180G），移动硬盘/拷贝交付，用户双击就能用，全程无网络。

**核心架构判断**：壳只做两件事——**一个窗口 + 一条关闭语义**。生命周期机器（splash 体检/健康轮询/心跳/崩溃重启≤5/单实例/优雅退出）boot.py 已建成，零重写复用；前端 Hash Router SPA 零改动进 WebView（ADR-002 §4 原文背书）。

**法理依据**：ADR-002 §5 重启条件 #1「分发非技术用户」已被商用方向命中 → 动工先立 **ADR-004**（S0）。

## 3. 壳层技术选型

| 方案 | 盘/内存增量 | 用户机依赖 | 新工具链 | 主要风险 |
|---|---|---|---|---|
| **pywebview**（WebView2） | ~3M / +50~80M | WebView2 Runtime + .NET FX（Win10/11 基本自带） | 无（pip 进 pydeps） | 成熟度中等，边角特性需 PoC 实证 |
| **Electron**（保底） | +~250M / +200~350M | 零（自带 Chromium） | Node（仓库已有 node-v20） | 重；对全家桶体积是零头 |
| Tauri 2 | ~5M / +60M | WebView2 | **Rust 构建链** | ADR-002 #3 裁定未解除，不推荐 |

**路线**：S0 用 pywebview 做 1 天 PoC，**六条门槛一条不过即转 Electron**（无淘汰风险）。
门槛：①splash(:5850)→主界面(:580x)切换正常；②窗口尺寸/位置记忆；③X 触发 /api/quit 并等收尾；④绘画页 canvas/GPU 正常；⑤中文输入法；⑥Win10 老机（无 VS/无 Python）跑通。
注：WebView2 缺失的用户机，交付硬盘里放 Evergreen 离线安装包（~100M）+ 首启检测引导（D4）。

## 6. 出门闸门（满足即"全家桶桌面软件封装完成"）

1. **家人测试法**：不懂电脑的人，拿到硬盘 → 拷贝（或直接盘上运行）→ 双击 → 激活 → 用起来，全程无指导无网络；
2. X 关闭后任务管理器零进程残留；
3. 崩溃注入 → 人话弹窗 + 诊断包可用 + 重试成功；
4. **防盗线实测**：整目录拷给别人 → 未激活被拦（403 全 API）；错码/他机码/改授权文件三连拒；watermark verify 能从包反查客户号；
5. 二次双击聚拢；冒烟+金母版零回归；
6. 24h 压测零静默死亡；模型许可证审计结论落档（发行级闸门）。

## 8. 前置与风险（诚实声明）

- **第 0 步 git 入库**：桌面壳/装配线新代码 + 既有 launcher/license 资产至今未提交版本控制，动工前先补（半天）；
- pywebview 成熟度由 PoC 硬门槛拦截，转 Electron 无沉没成本；
- 全家桶防盗 = 激活锁 + 水印**唯一两道**，本地软件防不死共识不变：目标是拷不走（激活拦）、泄露可溯源（水印查）；
- 水印对 272G 全量签名的耗时未实测（S6' 实测，预估 15~30 分钟/份，超标有降级方案）；
- 每次构建要拷 150~270G（约 30~60 分钟），全家桶时代"改一行重出包"的成本显著高于绿色包——版本节奏要克制；
- 精编版若砍 klein-9b 分片需同步改就绪检查代码（paint_engine.py:206-224）+ 回归。
