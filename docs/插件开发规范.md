# OmniSpace 插件开发规范 v1.0（统一要求，2026-09-16 拍板）

> 适用对象：为 OmniSpace 开发插件的所有开发者（含第三方）。
> 本规范分**机器闸**（导入时自动检查，不过即拒）与**审查闸**（入出厂
> 登记时人工逐行审查）两层；出厂级插件两闸都要过，用户导入级机器闸必过。
> 基类契约详见 `src/cutemamen/plugin.py`（单一真源，2026-09-16 统一）。

## 1. 两种插件形态与信任档

| 形态 | 内容 | 信任档 | 导入要求 |
|---|---|---|---|
| 纯数据包 | `.CuteMamen` 包（manifest + 权重 + 记忆），`base_model` 必须是**已知四类**之一（video.making / rust.coding / cubegpt.face / lora.adapter） | 用户·纯数据 | 直接导入，无需确认 |
| 带源码包 | `.CuteMamen` 包 + `.py` 源码文件，可实现全新插件类型 | 用户·含源码 | 必须通过源码静态安检 + 用户显式确认 |
| 出厂插件 | 上述任一形态 + 走 PR 逐行审查 + 入 `_SEED_PLUGINS` | 出厂·已审查 | 仓库内代码级登记 |

## 2. 源码硬性要求（机器闸：AST 静态安检，命中即拒）

1. **必须**定义 `ExpertPlugin` 的子类，并实现 `on_think(event, ctx)`；
   导入写法用双路垫片（两条加载路径等价）：
   ```python
   try:
       from .plugin import ExpertPlugin, PluginContext
   except ImportError:
       from omnispace.plugin import ExpertPlugin, PluginContext
   ```
2. **禁止导入**（含 from 形式）：`subprocess` `socket` `urllib` `urllib3`
   `requests` `http` `httpx` `ctypes` `pickle` `multiprocessing`
   `importlib` `webbrowser` `ftplib` `smtplib`。
3. **禁止调用**：`eval()` `exec()` `compile()` `__import__()` `open()`；
   以及 `os/shutil/sys` 的 `system/popen/kill/exec*/spawn*` 与任何对象的
   `unlink/rmdir/removedirs/makedirs/mkdir/startfile/write_text/write_bytes/
   read_text/read_bytes` 属性调用。
4. 允许的依赖面：标准库安全子集（`json/math/time/typing/dataclasses/
   collections/threading` 等）+ `numpy` + `PIL`（仅图像处理，不落盘）。
5. 确需文件 IO / 网络 / 子进程能力的，不写在插件里——向宿主提案
   桥接接口（走 PR 讨论），由宿主以受控方式提供。

## 3. 运行契约

- **事件入**：`on_think({"topic": str, "data": spec}, ctx)`；`data` 由
  调用方定义（如 video 的 keyframes/shots、rust 的 code）。
- **结果出**：返回 JSON 可序列化 dict（str/int/float/bool/小 dict/list）；
  **帧序列走专用 `frames` 键**（ndarray 列表）由宿主落盘，绝不塞进其他
  键——大数组进 JSON = 内存红线（POC2-A 实测 1080p 帧列 1.2GB）。
- **事件广播**：`ctx.emit(topic, payload)` 只发摘要与统计。
- **记忆**：working 用 `memory.set/get`；蒸馏知识用 `remember/recall`；
  事件流水由基类自动记录。不越权读写宿主状态。
- **资源**：纯 CPU；**不加载模型、不碰 GPU/显存**（显卡是独木桥，
  调度归宿主）；自报 `memory.footprint`，内存预算超限会被内核 LRU 淘汰；
  单次执行软超时默认 180s（调用方可覆写），超时插件置故障态。
- **生命周期**：`on_load(ctx)` 初始化、`on_unload()` 释放，幂等可重入；
  任何钩子抛异常都会把插件置故障态（unload 后可复位）。

## 4. 包格式（`.CuteMamen` = tar.gz，机器闸强校验）

```
<Name>.CuteMamen (gzip tar, ≤64MB, ≤64 条目)
├── manifest.json          # 必填 name/route/base_model；name 规则 ^[a-z0-9][a-z0-9_-]{0,63}$
├── weights/weights.npz    # numpy 权重（allow_pickle=False 读）
└── memory/
    ├── working.json       # {"entries": [{"key","value"}, ...]}
    ├── episodic.json
    └── semantic.json
```
条目白名单仅上述 5 个路径，多余条目=拒。打包示例：

```python
from src.cutemamen import save_pkg
from src.cutemamen.video_making import VideoMakingPlugin
save_pkg(VideoMakingPlugin("my-video"), "my_video.CuteMamen")
```

## 5. 开发者工作流

1. 参照 `src/cutemamen/video_making.py` / `rust_coding.py` 写源码（本规范 §2-3）；
2. 本地自测：套用 `tests/unit/test_plugin_runtime.py` 的夹具模式
   （`load_plugin_module` + `find_plugin_classes` + 直调 `on_think`）；
3. `save_pkg` 打包 → 设置页「插件」导入（或用户手动放包）；
4. 想成为出厂插件：提 PR——机器闸全过 + 维护者逐行审查（对齐
   RustCoding 登记审查口径）+ 入 `_SEED_PLUGINS`。

## 6. 用户侧须知（设置页文案基线）

- 蓝徽章=出厂·已审查；绿徽章=用户·纯数据（不引入新代码）；橙徽章=用户·含源码
  （**将在软件内部直接运行，请只安装信任来源**——导入时需勾选确认）；
- 用户插件上限 32 个、源码单文件 ≤256KB、包 ≤64MB；
- 用户插件文件存于 `data/plugins/imported/`，删除即清场。
