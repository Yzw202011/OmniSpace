## §1 目标与非目标

**目标（做什么）**
1. 插件可在 manifest 里**声明技能**：标明自己服务于哪个功能（chat/novel/comic/manga）、吃什么输入、干什么。
2. 四个创作功能页各有一个**「插件技能」入口**：列出当前可用的技能，用户显式调用。
3. 技能调用统一走**既有安全设施**：登记闸 + RAM 闸（3GB）+ 插件锁 + 软超时（180s）+ 信任三档 + 含源码档子进程沙箱——全部复用，零新建安全机制。
4. 技能产出**诚实可见、不静默改数据**：对话注入带标记；写作/漫画产出走"建议→用户采纳"两步。

**非目标（不做什么）**
- 不改 H3 主力视频链路（VIDEO_ROUTING_TABLE / manga-video 槽冻结令继续有效；漫剧正式视频生成不接插件）。
- 不动 feature_lock 互斥语义（技能调用不产生模型推理，不抢功能锁，走插件自己的锁）。
- 不做 LLM 自动工具调用、不做内核自动路由（D1/D5 拍板 A 的直接推论；未来要升级属新方案）。
- 不在本方案内产出新的出厂插件（D3）。
- 不碰打包台 / 激活台（范围冻结令）。

## §3 总体设计：技能插座（大白话：给四面墙各装一个插座面板）

```
                    ┌────────────────────────────────┐
                    │  插件 manifest 声明 skills 字段  │
                    │  [{id, feature, title, desc,   │
                    │     input: text|image}]        │
                    └───────────────┬────────────────┘
                                    ▼
              GET /api/v1/plugins/skills?feature=chat|novel|comic|manga
                    （登记表实时过滤 enabled + trust）
                                    ▲
     ┌──────────────┬───────────────┼───────────────┬──────────────┐
     │ AI对话       │ 写作台        │ AI漫画          │ 漫剧创作      │
     │ 技能按钮      │ 章节工具区     │ 格/页工具区      │ 预览按钮      │
     └──────┬───────┴──────┬───────┴───────┬────────┴──────┬───────┘
            ▼              ▼               ▼               ▼
   POST /dialog/skill  POST /novel/    POST /comic/skill  （已有）
   （文本进文本出）     chapter/{id}/   （图像进图像出，    POST /manga/
                      skill            落 output 返 URL）  video/preview
            └──────────────┴───────────────┴───────────────┘
                           ▼
            统一经 plugin_runtime.invoke（三道闸+沙箱）
                           ▼
        产出方式（诚实原则）：
        · 对话 → 单回合注入（下一问带 plugin_context，气泡上有标记）
        · 写作 → 建议对照 → 用户采纳（复用现有 PUT 写回）
        · 漫画 → 新图版本显示 → 用户选用
        · 漫剧 → 预览 mp4（现状不变）
```

**关键设计决定与理由**
1. **每个功能一个专用端点**（而非全走通用 /invoke）：通用 invoke 的 JSON 形态传不了大图像（ndarray 会被压成形状摘要），漫剧预览正是因为专用编组才能传帧。文本域虽可直接用通用 invoke，但功能端点才能做数据最小化裁剪（只传当回合/本章节，不传全量历史）。
2. **skills 声明进 manifest、解析进登记表**：`_PluginEntry.manifest`（registry.py:106）现成；出厂件在 `_SEED_PLUGINS` 补字段（:53），用户件在导入时校验入库。
3. **技能调用不抢功能锁**：不产生模型推理、不碰 GPU，走插件自身 RLock；RAM 闸兜底内存。
4. **沙箱档延迟诚实展示**：user_source 档走子进程，文本技能秒级、图像技能视体量；UI 显示"插件处理中…"，超时 180s 可在请求里下调。

## §6 总验收（做完的定义）

1. 四个功能页都能看到「插件技能」入口；无可用技能时优雅置灰（不报错不空转）。
2. `GET /plugins/skills` 三种信任档过滤正确；导入带非法 skills 的包被拒且报错带出路。
3. 对话：注入后气泡有标记、老请求回归零差异、SSE 首字不受影响（未触发技能时）。
4. 写作：建议→采纳→章节更新全链实弹；「放弃」不改任何数据。
5. 漫画：图像技能出图并可选用；原格不被覆盖。
6. 漫剧：预览回归基线（2s 级）不劣化。
7. 四闸全绿；每批独立 commit、独立可回退。
