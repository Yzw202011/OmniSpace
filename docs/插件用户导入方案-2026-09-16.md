# 插件用户导入方案 v1.0（2026-09-16 拍板「要做」，待开工令）

> 状态行：用户已拍板做本功能；本文为 §16.1 方案四段制方案书，**未开工**。
> 背景：当前插件只能「出厂预登记」（改代码 + 重启），前端零接线（全前端唯一
> plugin 命中是 Markdown 库参数）。本方案给终端用户一条图形化导入通道。

## 〇、产品形态一句话

用户在**设置页新增的「插件」区块**里点「导入」，选择 `.CuteMamen` 插件包
（可选再选一个 `.py` 源码文件），通过校验后插件进入列表，重启不丢，
可启停、可删除；出厂插件与用户插件用徽章区分信任档。

## 二、影响面

- **不改任何现有行为**：P2 漫剧⚡预览链、既有 6 个插件端点、出厂登记逻辑
  均不动；`plugins_info` 只增键；前端仅设置页新增区块。
- **安全面（本方案核心权衡）**：进程内插件=与后端同权限（P1 既定信任模型，
  非沙箱）。本方案的防线=①纯数据包零新代码（只可能是已知 4 类插件的
  权重/记忆变体，最坏=浪费内存）②含源码包强制用户显式确认+橙档常亮标记
  ③上传闸（魔数/白名单/上限）复用既有基建 ④发行包 make_dist 白名单制
  不变，用户导入件物理上不进发行树。**子进程隔离（真沙箱）仍留 P3+**，
  本方案的 trust 三档为其预留字段位。
- **磁盘**：`data/plugins/imported/` 用户可控（上限 32 个 ×64MB 理论极值，
  设置页删除即清）。
- **内核侧**：用户数据包进内核注册表后，`/plugins/kernel/think` 按路由可
  达（含源码档不进内核——内核原生注册表无其类，只走 OSP invoke）。
- **并发**：注册表 JSON 读写收进 `_global` 锁；导入端点串行化（文件落盘
  +登记原子化）。

## 四、风险与回退

| 风险 | 缓解 | 回退 |
|---|---|---|
| 用户导入恶意源码插件（进程内任意代码） | 强制大白话确认+橙档常亮+文档明示；发行用户自担（等同浏览器扩展模型） | trust 字段已分级，P3+ 子进程隔离可整体升级该档 |
| 上传炸弹（超大/畸形包） | 魔数+大小+条目白名单+64MB 上限（loader 既有闸全复用） | 单端点 revert |
| 注册表 JSON 损坏 | 读取容错（坏文件→备份改名+空表起步+日志），出厂登记不受影响 | 删 JSON 即回出厂态 |
| 撞名/覆盖出厂件 | 重名一律拒（含与 `_SEED_PLUGINS` 冲突） | — |
| 前端设置页膨胀 | 独立组件文件，Settings 只加挂载点 | 组件级摘除 |

整体回退：功能纯增量，三笔分批提交（后端/前端/实弹收口），任意一批
`git revert` 即回；用户数据侧删 `data/plugins/` 即恢复出厂态。

## 五、拍板确认点（默认值已选，可否决）

1. UI 位置：**设置页区块**（v1 不开独立导航页）——插件属高级功能，避免
   九页之外再加页。
2. 含源码档**本期就做**（带确认门）——若你要更保守，可砍掉源码分支，
   只放纯数据包导入（后端少一个端点参数、前端少一个确认框）。
3. 用户插件数量上限 **32**、源码单文件 **256KB**（拍板可调）。
4. 信任档文案：出厂·已审查 / 用户·纯数据 / 用户·含源码（大白话定稿可改）。
