## 一、接口散乱度 —— 🔴 别名前缀族实锤（本轮最重要发现）

**同域多前缀并存，且消费端跟着分裂**（装饰器逐一直读实锤）：

| 文件 | 端点数 | 前缀族分布 | 判读 |
|---|---|---|---|
| `src/api/draw.py` | 24 | **/draw ×13 + /paint ×10 + /art ×1** | 绘画域三前缀并存；/draw 与 /paint 基本同功能互为别名 |
| `src/api/dialog.py` | 22 | **/chat ×16 + /dialog ×6** | 对话域两前缀并存，且 /chat 是主体、/dialog 是少数——**与模块文件名倒挂** |

- 佐证：前册消费交叉核里 `/draw/upscale` 与 `/paint/upscale`、`/draw/inpaint` 与 `/paint/inpaint` **都被不同调用方使用**——别名不只是注册了，连消费方都各认各的前缀。
- **命名风格本体反而干净**：全部路径段统计 817 单词 + 42 kebab-case + 5 snake-case，**零混合风格**；仅存轻度 kebab/snake 双轨（5 个 snake 段：`ui_prefs`×2、`web_search`×2、`generate_h3_chain`，均在 system.py/video.py）。
- 合并前册：另有 16 个仅测试/工具消费端点、8 个死端点候选（参数路径型疑似误报）。

**定级**：🟡→🔴 功能可用但契约面呈「一域三名」，API 文档/前端封装/对账都会倍增成本。**建议**：别名族收敛（保留一族、其余标 deprecated 两个版本后删），或至少在 API 文档里显式登记别名映射表。
