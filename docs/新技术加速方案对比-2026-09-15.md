## P-1 图像链步数档：36 → 4/8 步【性价比最高】

### 现状 vs 方案

| 维度 | 现状 | 方案后 |
|------|------|--------|
| 绘画/分镜预览（comfy） | preset=quality → **36 步 / cfg 4.0**（`comfy_paint_engine.py:117-124`） | preset=fast → **4 步 / cfg 1.0**（蒸馏系原生档） |
| 漫剧关键帧链 | 显式 **steps=36 / cfg 4.0 / min_steps=28**（`keyframe.py:1417`），绕过 preset | 8 步起步档（关键帧带 PuLID/ReferenceLatent/多参考，保守半档） |
| 质量总督下限 | min_steps=28（V77 事故裁定：36×0.4=14 击穿质量地板） | 按新基准重定（8×0.5=4？需 A/B 定地板） |
| 单帧耗时 | 分镜预览暖态 15.4s（comfy 切换口径） | 预期 4~8s（步数线性折算 ⚠️未实测） |

### 为什么 36 步的历史理由已半失效 ✅
`keyframe.py:1412-1416` 注释自述：36 步是「v20 质量档」，理由是 **GGUF 量化噪声收敛更充分**——那是 GGUF 9B diffusers 时代的口径；现行 comfy 栈是 **fp8 单文件**（`comfy_paint_engine.py`），量化噪声形态不同。且本仓已做过绘画链 A/B：`tools/scratch/paint_preset_ab.py` + `data/comfyui/output/ab_preset_0000*.png`，结论「fast 4 步目验与 36 步基本无差」（`config.yaml:118-123` 自记）。**缺的只是关键帧全链一致性 A/B**（config 注释预设的门槛，即全量改造 v3 的 W4 未竟项）。

### 优点
- 零新依赖、零新权重、零新代码路径——只是档位切换 + 一次 A/B。
- 全产品图像链普惠：关键帧、分镜预览、资产图、绘画页、四视图外的所有 comfy 出图。
- 与已修的 D-LoRA 链正交（LoRA 挂载与步数无关）。

### 缺点 / 风险
- **低步数 × PuLID/ReferenceLatent 未验证**：多参考条件注入在 4 步下可能欠收敛（社区经验：4 步手部偶欠、6~8 步更稳）。
- cfg 语义变化：蒸馏档配 cfg 1.0，关键帧现用 4.0——A/B 必须把 (steps, cfg) 当组合测，不能只动步数。
- 质量总督深度降档公式需重校（min_steps 语义）。
- 四视图 legacy-4b 链（turnaround_engine=legacy，独立开关）不受益——它是 diffusers 分件栈、20 步口径，另案。

### 四段制要素
- **改动清单**：`backend/config.yaml`（preset: quality→fast 或新增 keyframe_steps 档）、`backend/api/manga/keyframe.py:1417`（36→8 + cfg 联动）、质量总督 min_steps 常量重定；配套 A/B 脚本入 `tools/scratch/`。
- **影响面**：comfy 图像链全部消费方（draw/预览/资产/关键帧）；legacy 链与四视图不动。
- **验证方法**：固定 3 镜（特写/中景/多角色）× 3 组合（36步基准 / 8步+cfg4 / 4步+cfg1）同种子出图，PuLID 一致性（DINOv2 或目验）+ 多参考遵循度对照；通过后拨默认，前端无感知。
- **风险回退**：config 一行拨回 quality，重启生效；A/B 不通过则维持现状，报告留档。

## P-2 H3 SageAttention 增益实测【零风险信息收集】

### 现状 vs 方案
- 现状：`--use-sage-attention` 随 ComfyUI 进程全局开启（`comfy_proc.py:306-308`，config `comfyui.use_sage_attention: true`）；图像侧已实测（多角色格 426s→350s，+18% ✅）；**H3 视频侧增益从未测过** ⚠️。
- 方案：同一镜（同种子/同提示词/同 720p）在 sage on/off 各跑 2~3 次，取墙钟中位数对照。

### 优点
- 纯测量，不动一行代码，半天出数。
- 若实测正收益 → 为 P-3（二采抬分辨率）腾出预算；若零收益 → 排除一个假设，省得后面方案建立在虚假前提上。
- ComfyUI 官方 H3 文档口径「约提速一倍、质量损失极小」🔶；SageAttention 2.2 在 4090 上 H3 实测最高 +44%（平均 24.3%）🔶——我们的 18%（图像侧）偏保守，视频侧值得测。

### 缺点 / 风险
- 无实质风险。注意两点操作纪律：sage 开关需后端重启让 ComfyUI 重拉（进程空闲 300s 自关后自然换）；测前过 GPU 活动门（§16.6，近 5 分钟无用户任务）。
- 测量噪声：单镜波动大，须多跑取中位数；结论标注置信口径。

### 四段制要素
- **改动清单**：无代码。`config.yaml` 翻 `use_sage_attention` 各一次 + 一个对照脚本。
- **影响面**：无（测完即复原）。
- **验证方法**：两组墙钟差 ≥10% 判有效；产出对照表入本方案附录。
- **风险回退**：config 复原即回。

## P-3 H3 二采（两段式潜空间放大）：720p → 1080p+【画质上限突破】

### 现状 vs 方案

| 维度 | 现状 | 方案后 |
|------|------|--------|
| 分辨率档 | 480p(864×480,≤15s/镜) / 720p(1344×768,≤8s/镜)（`h3_chain_engine.py:71`） | 新增 1080p 档：低分辨率初采 → 潜空间放大 → 二次采样精修 |
| 单镜耗时 | 720p 6 步（社区同档参考：768p 8 步≈100s 🔶） | 约为现档 ×2（两次采样）⚠️估 |
| 显存 | 720p 常规 | 社区 6GB 显卡可跑双采 4K 🔶 → 16GB 无压力 |
| 清晰度 | 720p 天花板（H3 官方原生上限 2K） | 直出 1080p+，高动态模糊亦有改善（社区口径 🔶） |

### 优点
- **直击产品痛点**：漫剧成片分辨率是我们与竞品对标的可见短板之一；二采是社区验证过的最短路径（多个独立教程同结论 🔶）。
- 不换模型、不动 H3 主力路由（仍是 minimax-h3 本体），只在工作流内加采样段。
- 与 P-4（双时钟）可叠乘：二采加的耗时可用双时钟抵回一部分。

### 缺点 / 风险
- **触碰冻结区**：2026-09-06 用户令「漫剧视频主力=minimax-h3 禁止改动」——改 `h3_chain_workflow_api.json` 属 H3 链工作流，需明确解冻拍板（本方案即申请）。
- 单镜耗时约翻倍：产能换画质，产品上应作为「高清档」而非默认档（按时长/档位现有机制挂新档）。
- 工作流手术风险：API 格式 JSON 增加节点链（latent 放大 + 二段采样器 + 步数分配），音频 VAE 链（`h3_chain_engine.py:326` audio_vae 已接线）必须不被破坏；队列取消/进度回调要跟上二段节奏。
- 社区「接近 4K」口径有营销水分（官方原生 2K 上限内做文章），验收按 1080p 实测目验定。

### 四段制要素
- **改动清单**：`h3_chain_workflow_api.json`（新增二采节点组）、`h3_chain_engine.py`（质量档位表 _QUALITY 增 1080p 档 + 档位→工作流参数映射）、前端模型配置画幅选项。
- **影响面**：漫剧视频生成链（唯一）；音频链、取消链、进度广播需回归。
- **验证方法**：同镜 720p 直出 vs 二采 1080p 对照（清晰度目验 + 单镜耗时记录）；音频完整回归；队列取消回归。
- **风险回退**：档位表不挂默认，新档开关关闭即回现状；工作流 JSON 在 git 内可整体还原。

## P-4 T8 双时钟采样器：H3 采样段再提速 ~100%【社区黑科技试点】

### 现状 vs 方案
- 现状：H3 采样 6 步（Turbo LoRA 区间 4~8，`config.yaml:156-159`），sage 全局开；无步数分离机制。
- 方案：引入 [T8mars/comfyui-minimax-h3-audio-T8](https://github.com/T8mars/comfyui-minimax-h3-audio-T8) 节点包的双时钟采样（步数分离：高低噪声段分时钟调度），社区口径「加速 LoRA 之上再提速约 100%」🔶（B站 BV1kzuJ6SEQk / YouTube 实测「6 步时代·无损近一倍」🔶）。

### 优点
- 提速维度与 sage（内核）和 Turbo LoRA（步数）正交，三者叠乘。
- 我们 ComfyUI 0.34.0 ≥ 节点包要求的 0.30 ✅，装 custom_nodes 即可试，门槛低。
- 节点包顺带带人脸修复/低去噪细化等能力，与二采（P-3）可组合（二采加的耗时用它抵）。

### 缺点 / 风险
- **第三方依赖**：个人维护的开源节点包（同类的 StoryDiffusion/ToonCrafter 引进模式有先例，但维护断供风险真实存在）。
- 「无损」「+100%」均为社区口径未独立复验 🔶；「无损」在本仓必须以多角色一致性目验复核（我们的 H3 链带资产参考，与纯 T2V 工况不同）。
- 触碰 H3 冻结区（同 P-3，需拍板）；音频链兼容性需实测（T8 包即 H3-audio 生态，理论同源 ⚠️）。
- 4 步区间我们本就不去（音频崩 🔶 + 大动态 ghosting 本仓 config 已记），双时钟解决的是等质量下提速，不是进一步压步数。

### 四段制要素
- **改动清单**：`custom_nodes/` 装节点包；`h3_chain_workflow_api.json` 采样段换 T8 采样器节点；config 增门控开关。
- **影响面**：H3 采样段；验收不过即整体回退，不残留。
- **验证方法**：同镜同种子 on/off 对照（墙钟 + 一致性目验 + 音频回归）；≥30% 提速且质量不降才转正。
- **风险回退**：工作流换回原采样器节点 + 节点包停用（不删，隔离观察）。

## P-5 vLLM 0.28 升级 + DFlash 投机解码：文本 2~3×

### 现状 vs 方案

| 维度 | 现状 | 方案后 |
|------|------|--------|
| 推理引擎 | vLLM 0.27.1（py313 子进程，sleep 补丁常驻） | vLLM ≥0.28.0（DFlash2 门槛 🔶官方文档口径） |
| 投机解码 | MTP：9B 有 model_mtp 权重已启用 / 8B-awq 无权重被忽略（日志实证 ✅） | DFlash 块扩散草稿模型：**Qwen3.5-9B 恰有社区草稿**（[guglxni/Qwen3.5-9B-abliterated-DFlash](https://huggingface.co/guglxni/Qwen3.5-9B-abliterated-DFlash)，5 层轻量草稿 🔶） |
| 文本吞吐 | 对话首字 0.29s（暖态 ✅）；长文本（小说/分镜词/翻译）为吞吐瓶颈 | 消费级口径 2~3× ⚠️（NVIDIA 15× 为数据中心大模型口径 🔶） |

### 优点
- 收益集中在真实痛点：对话已够快，**长文本生成**（小说章、批量分镜词、翻译管线）才是慢的主场景。
- vLLM 0.26→0.28 升级本就是《底层架构升级方案》V1 待拍板项——本方案是给它**加菜**而非新开战线；且 0.28 可能携带上游 sleep_mode 修复（现 0.27 靠本地补丁常驻，升级时需重验 ✅既知事实）。
- 草稿模型与目标的家族匹配是硬前提：guglxni 草稿目标正是 Qwen3.5-9B（Reddit 实测提醒：跨家族草稿会反向劣化 🔶）。
- 意外联动：该草稿是 abliterated 变体——与《无限制模型调研》的 4B-abliterated 候选同一生态，若将来换脑可复用投机解码基建。

### 缺点 / 风险
- **升级本体风险为主**：0.27→0.28 跨版本的 Windows/py313/torch2.13 四坐标兼容需全验（调查纪律：四坐标锁死）；sleep 补丁基线要重对。
- **W4A16 量化目标 + 投机解码**的接收率未知 ⚠️（草稿按 fp 目标训练，量化目标的接受率可能打折，须 A/B 实测吞吐）。
- 8B-awq（VL 模型）无对应草稿（DFlash 支持 VLM 是库能力，qwen3-vl-8b 专用草稿未见 ⚠️）——8B 档位收益存疑。
- 与 MTP 二选一（同引擎同槽位）：9B 现在 MTP 已有增益，DFlash 相对 MTP 的边际增益需实测，可能不如宣传口径。

### 四段制要素
- **改动清单**：runtime/py313 环境 vLLM 升级、`vllm_service.py` 启动参数（草稿模型接入）、sleep 补丁重验；下载 guglxni 草稿权重入 models/（manifest 登记）。
- **影响面**：全部文本生成（对话 SSE/小说/分镜词/翻译）；GPU 常驻显存 +草稿约 1~2GB ⚠️待查实。
- **验证方法**：四坐标兼容预检 → 冒烟（加载/首字/吞吐）→ 长文本基准（同 prompt MTP vs DFlash 墙钟+接受率）→ 回归 774 项测试。
- **风险回退**：vLLM 版本回滚 0.27.1（py313 环境快照保留）；草稿不接即回 MTP 现状。
