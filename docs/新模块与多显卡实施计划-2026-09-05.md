## §1 批1：多卡地基（D2）

### 1.1 设计总纲：资源域（Resource Domain）

把"功能 → 显卡"的分配收敛为一个新单源模块 `backend/engines/gpu_domains.py`：

- 新 config（config.yaml `gpu` 节追加，config.py:88-92 同步）：
  ```yaml
  gpu:
    primary_device: 0          # 已有
    auxiliary_device: 1        # 已有
    secondary_offload: false   # 已有
    feature_devices:           # 新增：功能→卡分配，缺省全 0 = 现状
      dialog: 0
      paint: 0
      video_gen: 0
      training: 0
  ```
- `resolve_feature_device(feature) -> int`：读 `feature_devices`，并用 `enumerate_gpus()`（gpu_backend.py:348）校验索引存在；**配置指向不存在的卡时回落主卡 + 打 warning，绝不允许因配置错误起不来**。
- **单卡快速路径铁律**：`device_count() <= 1` 时所有 API 原样走旧逻辑（语义=全在 0 号卡），保证单卡机器行为逐比特不变——这是批1 的回归安全网。

### 1.2 vram_manager 设备化（backend/engines/vram_manager.py）

| 现状（行号） | 改造 |
|---|---|
| `__init__` 只探 0 号卡总量（:59） | 循环 `device_count()` 探测全部卡 → `_vram_totals: dict[int, float]`；0 号卡仍存 `_vram_total_mb` 兼容旧字段 |
| `get_usage()` 读 `memory_allocated(0)`（:214） | 加可选参 `get_usage(device=None)`（None=主卡，返回结构不变+新增 `devices` 列表）；新增 `get_device_usage(i)` |
| `get_available_mb()` 读 `mem_get_info(0)`（:239） | 加可选参 `get_available_mb(device=None)` |
| `track_alloc/track_free` 无设备维度（:74,94） | 加可选参 `device`，账本记录归属卡；`reset_bookkeeping` 按卡过滤 |

旧调用方（准入闸门 vllm_service.py:351、调度器 monitor.py:103、api/hardware.py:48 等）**不改签名照常编译**，参数缺省即旧行为。

### 1.3 feature_lock 资源域化（backend/middleware/feature_lock.py）——批1 核心语义变化

现状：单全局持有者 `_holder`（:50），四功能全互斥（:25-30）。

改造为**按卡互斥**：
- 内部 `_holders: dict[domain, str]`，domain ∈ {"0","1",…,"remote"}（"remote" 伪域为批3 远程引擎预留——远程对话不占本地卡，天然不与绘画冲突）。
- `acquire(feature)`：先 `resolve_feature_device(feature)` 得 domain；阻断规则从"有别人持有就拒"改为"**同 domain 有别人持有才拒**"→ 双卡机上"对话占 0 卡 + 绘画占 1 卡"可并行。
- 兼容语义：
  - `active_feature` 属性保留：单卡=现行为；多卡多持有时返回**主卡域持有者**，完整持有表走 `status()`（新增 `holders` 数组字段，旧字段原样保留）。
  - `get_block_reason` 文案带卡号（"绘画正在 1 号卡进行"），单卡文案不变。
  - 同功能重入计数（:53-59 审计 P1-1 修复）按 domain 分别计数。
- **热保护维持全局**（thermal_guard 单卡实现），per-device 温度门控列入后续批，本批不扩。
- **约束：paint 与 video_gen 默认绑同一张卡**（config 缺省都=0），因为两者共用同一个 ComfyUI 单实例（comfy_proc.py:39 端口单例）——异卡分置须等 ComfyUI 多实例批，配置校验时若发现二者异卡直接告警回落。

### 1.4 引擎绑卡通道（让"按卡分配"真的生效）

- **vLLM（vllm_service.py）**：`start()` 拼环境变量处（:565-590）按 `resolve_feature_device("dialog")` 注入 `CUDA_VISIBLE_DEVICES=<i>`（launcher 已有透传白名单 launcher.py:418，但 vLLM 子进程是 `os.environ.copy()`，需显式 set）。附注：`--tensor-parallel-size` 本批**不加**，参数通道留到专业卡批。
- **ComfyUI（comfy_proc.py）**：spawn 命令（:242-251）追加 `--cuda-device <i>`（并显式设 `CUDA_VISIBLE_DEVICES`，因为 ComfyUI main.py:48-52 在 Windows 下未指定时强制 =0）。
- **进程内小模型**（qwen_gguf_stream.py:194,261、vector_db.py:258 等直接 `.to("cuda")` 的点）：本批只登记清单不改代码——它们都是小模型，默认跟随 0 号卡即可；改绑列后续批。

### 1.5 release_for_module 按卡释放（backend/services/model_manager/__init__.py:1084）

`release_for_module(target_feature)` 增加"目标卡"语义：只卸载**目标卡上**的模型给目标功能腾地方，别的卡上无关模型不动。单卡（全部=0 号卡）时行为与现在完全一致。

## §3 批3：远程引擎模式（D3）

### 3.1 R1 远程对话引擎（本批主体）

- **新后端类** `backend/services/inference/backends/remote_backend.py`：实现现有 `DialogBackend` 协议（backends/base.py，现有 VLLMBackend 按量化格式路由 :26-34），路由规则加一条：config `dialog.backend=remote` 时选它。
- **配置**（config.yaml `dialog` 节）：`remote_base_url`（如 `http://192.168.x.x:8000`）、`remote_api_key`（可选）、`remote_model`、`remote_timeout`。
- **协议**：OpenAI 兼容——`POST /v1/chat/completions`（流式走 SSE 透传给现有对话 UI）、健康检查 `GET /health`（vLLM 标准）。
- **未就绪铁律**（用户产品铁律：不许"再点一次"）：远端 vLLM 冷启动装载要几分钟 → `ensure_loaded` 语义=健康探测+有界轮询（≤5 分钟，与本地链 dialog.py:649-673 同口径），超时才报错且报错带出路指引（"服务器 192.168.x.x 正在装载/不可达，检查地址或稍候"）。
- **台账**：ModelManager 登记远端条目，`vram_local_mb=0`、`host="remote"`；`release_for_module`/空闲看门狗/RAM 闸门**跳过远端条目**（本地无显存可释放，别误杀）。
- **功能锁**：remote 对话=批1 资源域的 `"remote"` 伪域 → **远程对话与本地绘画天然并行**，这是 D3 送 D2 的红利，计划内写明。
- **UI**：设置页加"远程推理服务器"卡（地址/密钥/测试连接按钮）；模型管理页照 readiness 横幅模式显示远端引擎状态。
- **安全**：桌面端出网目标=用户自己的服务器；api_key 可选；不落盘明文密钥以外的配置。

## §4 风险与开放问题

1. **实机双卡验证缺口**（最大风险）：批1 全部多卡逻辑只有 mock 单测背书，语义设计再稳也需实机复验；列永久待办。
2. **feature_lock 语义变化的回归面**：全后端 15+ 处 acquire 调用点，靠"单卡快速路径逐比特不变"+全量回归兜底；哨兵测试锁死。
3. **小说长文 vs 4K/8K 上下文**：MVP 靠"前情摘要链"硬扛，正文质量上限受本地小模型制约——诚实预期：批3 远程大模型落地后才有"能看的长篇"。
4. **对话/绘画异卡并行的新故障面**：GPU 温度、电源、显存叠载的组合是全新的（现有机 stability 经验全在单卡）；双卡实机验证时按「跑前 /free 防叠载」铁律重测。
5. **远端服务器运维归属**：地址/密钥/升级是用户侧运维，产品只承诺"连得上就能用"。
