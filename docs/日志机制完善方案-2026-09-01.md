## 1. 现状盘点（大白话）

**已有的家底（不错，别推倒重来）：**

| 层 | 是什么 | 落在哪 |
|---|---|---|
| ① 事件日志 | 大白话事件（"模型已加载/热切换/异常"），带级别+模块，可筛选 | SQLite（event_log 服务），30 天自动过期 |
| ② 流程追踪 | 一次生成的全链路（flow_id 贯穿 API→调度→引擎，节点级输入输出/耗时/资源快照/卡住分析） | SQLite（flow_trace 服务） |
| ③ 原始日志 | backend.log / error.log / vllm-server.log 尾部在线查看（白名单防任意读取） | logs/ 目录文本文件 |

**四个真实缺口：**

1. **没有轮转**：backend.log 已 8.2M，单文件无限长——出问题时几十万行里捞针，文件大到编辑器都卡
2. **没有导出**：在线只能看尾部 2000 行；事件库/流程库的数据出不去；发给别人（或未来发给售后）无门
3. **原始日志不能翻找**：没有级别/关键词/时间过滤，只有"最后 N 行"
4. **logs/ 目录是垃圾场**：45M 里混着调试脚本、帧目录、5 份编号 boot 日志（boot_out2~5）——排查时不知道哪个是真身

**打个比方**：家里有三本账（事件账、流程账、流水账），记得还行，但流水账永不装订越写越厚、没法复印寄人、翻旧账只能从最后一页看、而且记账桌上堆满杂物。

## 2. 要补的四件事

### 2.1 轮转装订（日志不再无限长）
- backend.log / error.log / vllm-server.log 按大小切割（单份 50M，各留 5 份滚动）
- boot/launcher/comfy 启动日志统一命名（boot.log 单名滚动，不再 boot_out2/3/4/5 编号繁殖）
- 与现有 30 天过期清理协同（轮转管大小，过期管时间）

### 2.2 一键导出（诊断包）
日志页加「导出诊断包」按钮，后端打 zip，内容：

| 内容 | 说明 |
|---|---|
| 时间段内事件 | 按所选时间范围导出（JSON/CSV 双格式） |
| 失败流程明细 | 最近 N 条 error/cancelled 流程的完整节点链（含输入输出摘要） |
| 原始日志切片 | 所选时间段前后各 N 行，或整个轮转文件（可选档） |
| 系统快照 | GPU 型号/驱动/显存占用/RAM/OS/Python 版本/模型清单（复用 /hardware/info） |
| 清单文件 | manifest.txt：导出时间、范围、包含项、版本号 |

**脱敏开关**（导出弹窗勾选）：
- 默认含提示词等用户内容（自用排障需要）
- 勾选「脱敏」：提示词/描述词字段打码（发给他人或未来售后场景）

### 2.3 原始日志翻找（过滤）
日志页原始日志区升级：级别过滤（INFO/WARN/ERROR）+ 关键词高亮 + 时间跳转；后端 /logs/raw 支持 grep 式参数（仍限白名单文件，行数上限防打爆）。

### 2.4 目录治理
- logs/ 只留 *.log 与轮转文件；调试脚本/帧目录等历史杂物一次性归档到 tools/debug_archive/（不删，先挪）
- 启动链日志输出统一到 boot.log（launcher/boot/stop 共用）

## 3. 三档方案，选一个

**方案 A：轻量补齐（1~2 天）**
轮转 + 导出基础版（zip 含事件+原始日志+系统快照，无脱敏）+ boot 日志统一。**够自用，最快见效。**

**方案 B：标准版（3~5 天）【推荐】**
A 的全部 + 原始日志过滤翻找 + 失败流程明细入包 + 脱敏开关 + 目录治理。**自用排障顺手，且就是未来发行版售后诊断包的雏形**（封装方案里"一键收集日志"那条 TODO 直接落地）。

**方案 C：完整体（1~2 周）**
B 的全部 + 资源曲线（显存/RAM 时间线图，数据源 ResourceSnapshot 已有）+ 崩溃后"事后取证包"（重启检测到上次异常退出自动标记相关日志）+ 前端 console 错误采集入事件库。**运维级，发行后有必要再上。**

## 5. 技术要点备忘（施工用）

- 轮转：`logging.handlers.RotatingFileHandler(maxBytes=50M, backupCount=5)`；uvicorn access log 一并接管
- 导出：`tempfile + zipfile` 流式写响应（FileResponse）；events/flows 从 SQLite 查询后序列化；白名单文件按 mtime 过滤时间段
- 脱敏：对 prompt/description/content 字段做 `len>8 ? 前4后4加***` 式打码；manifest 记录脱敏与否
- /logs/raw 过滤：白名单文件 + `keyword`/`level`/`after`/`before` 参数，行数硬上限 5000，命中行上下文 ±3 行
- 大文件 tail：当前实现整文件读入再切片（8M 尚可，轮转后恒小）；过滤版改从尾部倒序扫描
- 目录治理：一次性 `tools/archive_debug_debris.py`（移动而非删除）+ CLAUDE.md 记录"logs/ 只放 log"的门规
