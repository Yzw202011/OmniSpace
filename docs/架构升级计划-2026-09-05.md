## 0. 大白话总览（先看这页）

**先回答一个前置问题：要不要换编程语言/框架？——不换。**

现在的组合是"前端 TypeScript + 后端 Python + 桌面壳 pywebview"，这恰好是 AI 桌面产品的最优解：AI 生态全在 Python（换语言=丢掉全部引擎链），前端类型检查四道防线（mypy+tsc+ruff+pytest）刚建成（09-05 收官），换栈等于把刚盖好的房子推倒重盖，零收益。**架构升级 ≠ 换语言，而是在现有地基上加固和换代。**

**这辆车的现状**：车架（调度/队列/一致性框架/模型底座/授权发行）已经很好，四道质量闸门 09-05 刚全部上岗。接下来分四层推进：

| 层 | 干什么 | 比喻 | 风险 | 粗估 |
|---|---|---|---|---|
| **A 地基加固** | 修 2 个 P0 缺口（安全补丁+提交内存闸门）+ 144G 磁盘腾挪 + 压测取证 | 补水电管线、清地下室 | 低（多数不撞 GPU） | ~1 周内穿插 |
| **B AI 能力换代** | 换脑子→换画笔→换摄像机（三阶段，真源《AI计划》） | 换三台发动机 | 中（显存压线/新件兼容） | 3~5 周 |
| **C 工程底座** | 关键帧插座化 + 评测框架 + 债务递减 + 语音试听 | 给车装仪表尺和标准插座 | 低 | 穿插进行 |
| **D 发行冲刺** | 打包台三件尾活 + 许可证法务 + v5 安装体验 | 上牌卖车 | 中（法务/周期长） | 6~7 周 ⚠️ |

**如果只记一句话**：A 层两个小补丁先修（半天级），然后按《AI计划》阶段一"换脑子"开动——性价比最高、风险最低、收益面最广。

## 3. 阶段 A：地基加固（先行，多数不撞 GPU）

### A1 rmtree 路径穿越修复（P0-1，半天）

- **改动**：style 删除接口对路径做 realpath 归一 + 白名单目录前缀校验（一行修复 + 一条单测）。
- **验收**：单测覆盖 `../` 穿越用例被拒；ruff + pytest 绿。
- **回滚**：git revert 单提交。

### A2 提交内存闸门补口（P0-2，半天~1 天）

- **改动**：resource_guard 新增提交内存维度——Windows 原生口径 ctypes GetPerformanceInfo 读 CommitTotal/CommitLimit（与 WER RADAR 同源，✅ 方向），psutil 作备选；三档阈值沿用 80/85/90，危急档并入现有 shed_memory 链。
- **为什么现在做**：《AI计划》阶段三 Wan-Animate CPU 卸载吃提交内存（空闲 49.5G），现有闸门盯不住——**这是 A 层与 B 层之间唯一的硬依赖**。且不止服务 B3：现役 qwen-image-2512 流式模式本就要 28G+ RAM（提交口径），此刻已在危险区活动，A2 上岗对现网即有保护价值。
- **定位诚实化（09-05 复查）**：A2 是"仪表盘+止损阀"（能看见、能 shed、能留证），**不是"保险箱"**——它不阻止 CPU 卸载件自身吃满提交内存，只保证暴毙前有证据、能止损其他模块。
- **验收**：人为制造提交内存压力（大页申请进程），闸门触发 shed_memory 且心跳历史留痕；现有物理 RAM 三档回归不破。
- **回滚**：新维度加开关，关即回旧口径。

### A3 24 小时挂机压测（P1-1，挂机 1 天 + 取证半天）

- **内容**：新配置（A2 上岗后，最好 B 阶段一换脑后）挂机 24h：对话/绘画低频轮转任务 + 心跳/资源曲线取证，对照静默死亡三件套是否零触发。
- **纪律**：与用户约窗口（占机器一整天）；与《GPU 活动门》一致，压测期间不做其他 GPU 验收。
- **验收**：心跳 jsonl 全程无断档、无 RADAR 崩溃记录、资源曲线无爬坡失控。
- **两种结局都要预设（09-05 复查）**：复现 → 按资源曲线定位嫌疑人，修复后复测（根因才算闭合）；不复现 → 根因仍属悬案，发行带风险条款（心跳防线在）——不能把根因闭合全押在一次压测上。

### A4 隔离区 144G 真空删（P1-2，🔴 不可逆，需拍板）

- **时机**：09-08 观察期满，检查单四条全过才动手（收尾计划 §1.2 原文照用）：观察期无异常 / 冒烟+dir_audit 当日绿 / 用户确认功能无缺失 / 逐目录 du 留档后 rm。
- **收益**：E 盘 140G → ~280G，为 B 阶段模型换血（进一件退一件）腾出余量。

### A5 dir_audit 4 项存量清理（P2-2，半小时）

- 启动打包台.bat/.exe + packaging_console 目录登记白名单；根 console.log 清理（先确认为调试遗留）。

### A6 对话排队改进（P1-3，1 天，待拍板 → 决策 #8）

- **改动**：绘画持锁时对话请求从"秒拒"改"排队 + 广播位次"——复用图像队列单 worker + queue_position 的现成模式（image_queue.py ✅ 在库），对话引擎加一条排队通道；UI 复用"排队中·前 N"现成组件。
- **验收**：绘画生成中发起对话 → 秒回"排队第 N 位"→ 就绪自动续跑（产品铁律：不许"再点一次"）；取消即出队。
- **回滚**：配置开关切回秒拒。
