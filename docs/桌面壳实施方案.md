## 一、目标与总验收口径

**一句话**：把 OmniSpace 从「launcher + 系统浏览器」变成普通用户双击图标即用的 **Windows 桌面应用**——一个原生窗口装下全部界面（点火 HUD → 激活卡 → 主界面），关闭即全链收尾，任务管理器零进程残留，Win10/11 白机可装可用。

**总验收 = ADR-004 §5 六门槛 + 出门闸门 #2**（S4 逐条实测存证）：

| # | 门槛 | 判据 |
|---|---|---|
| ① | 出窗渲染 | 双击 exe → 原生窗口出 splash HUD → 就绪进主界面（S0 已验 ✅） |
| ② | 窗口尺寸/位置记忆 | 关闭重开，窗口回到上次位置与大小 |
| ③ | X 触发优雅退出 | 点 X → 按 D2 三态收尾 → 全进程树退出零残留 |
| ④ | 绘画页 GPU 渲染 | 主界面绘画页出图正常（WebView2 硬件加速） |
| ⑤ | 中文输入法 | 全输入框中文录入正常（含长句/候选窗位置） |
| ⑥ | Win10 老机 | 无开发环境的 Win10 机器上 ①~⑤ 全过 |

## 三、总体架构（一窗口 + 一条关闭语义）

### 3.1 进程拓扑（发行包形态，全部品牌名）

```
双击 启动OmniSpace.exe (C 桩, omnispace_exe.c)
  └─ OmniSpace-Boot.exe  ← boot.py（唯一生命周期监督者，本进程内开壳窗）
       ├─ [壳窗] pywebview/EdgeChromium(WebView2) ←—— 装下全部 UI 的唯一窗口
       │     内容状态机：点火HUD(splash :57xx) → 激活卡(同 splash P7) → 主界面(:5800)
       ├─ OmniSpace-Backend.exe（uvicorn 后端）
       │     ├─ OmniSpace-LLM.exe（py313/vLLM）
       │     └─ OmniSpace-Engine.exe（ComfyUI）
```

**壳跑在哪个进程**（S1 首个设计决策，双路线备好）：
- **主路线：壳内嵌 boot 进程**——boot 在 `--no-browser` 分支 import webview 出窗（webview.start 跑独立线程，boot 主循环照旧）。优点：关闭语义直连（关窗=boot 退出信号，无跨进程 IPC）、进程树天然单根。ADR-004 原文即此意（「经 --no-browser 分支出窗」）。
- **兜底路线：独立壳进程 OmniSpace-Shell.exe**——若同进程踩坑（如 webview 线程与 boot 事件循环互扰），壳独立进程+HTTP IPC（壳↔boot 走本机回环）。资产位已建（brand_exe），切换成本 1 天内。
- 判定点：S1 排障期实测定，定案后在本节标注 ✅ 并写明证据。

### 3.2 窗口内容状态机（splash 零改造的关键）

```
双击 → boot 起点 → splash 服务器就绪(~1s) → 壳窗开在 splash URL
  → 点火 HUD（五阶段时间线实时刷）
  → 门禁启用且未激活 → P7 激活卡（现成，激活完成自动放行）
  → redirect_ready → 「进入 OmniSpace」→ 页面内导航进主界面 :5800（WebView 内生效，splash/前端零改动 🔶 S1 实测确认）
  → 失败/超时态 → splash 错误卡（人话+日志）+「导出诊断包」按钮（挂 /logs/export）
```

依据：boot `refresh_license`/`maybe_redirect_ready`（boot.py:825-860）已实现「EULA✓ 且（门禁未启用或已激活）才放行」；splash 页面内自导航（:582 进入按钮）📖。**壳要做的只是开窗+等它自己走完**。

### 3.3 单实例聚拢（壳模式新语义，顺带销案「待拍板小修」）

现状：二次双击 → 新 boot 探测到既有 splash（build_id 闸门）→ `webbrowser.open` 复用后退出（boot.py:494-510）。壳模式下 `webbrowser.open` 无意义，改为：**新实例向既有实例的 splash 服务器 POST `/api/focus` → 既有壳窗前置激活（webview `window.show()`）→ 新实例退出**。
这同时解决了冲刺计划挂着的「二次双击开终态启动页 vs 直达主界面」待拍项：**聚拢到既有窗口本身**——窗口内容自动处于正确状态（就绪=主界面/未就绪=HUD/未激活=激活卡），无需「直达 :5800」的特判，语义更简单。开发模式（非壳）维持 `webbrowser.open` 不动。
