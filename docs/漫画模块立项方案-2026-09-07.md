## 〇、一句话方案

漫画模块 = **现有生图底座（队列/风格包/PuLID 一致性/ComfyUI 生命周期全部白拿）+ 新产品面（漫画页：多格排版 + 对话框 + 整页导出）**，前端替代 /paint 页；角色一致性走已量产验证的 PuLID-Flux2 + ReferenceLatent 多参考链（漫剧 face_sim 0.846），StoryDiffusion/ToonCrafter/MangaNinja 三插件因**当前 GitHub 网络不可达（连接重置，实测）**列为离线包/网络窗口的升级备选，不阻塞 M1。

## 一、为什么"替代"成立（侦察结论，file:line 见探查记录）

绘画页的承重墙与漫画模块完全同源，替代只是换"产品面"：

| 现成件 | 位置 | 漫画模块怎么用 |
|---|---|---|
| 统一生图队列 | image_queue.py（绘画/关键帧/资产图三族共用） | 新增 kind=comic_panel 的 runner，分格批量生图白拿排队/取消/优先级/云端道 |
| 角色一致性 | comfy_paint_engine.py:260-394 PuLID+ReferenceLatent 8 图多参考链 | 漫画"每格保持同一角色"直接复用；漫剧已量产验证（face_sim 0.846） |
| 风格包 | gen_router.py:131 STYLE_PACKS 28+ 包（含 comic_en 美漫/manga_bw 黑白/manhwa 韩漫） | 纯后端 prompt 工程，漫画页直接挂风格卡 |
| ComfyUI 生命周期 | comfy_proc.py（按需冷启/空闲自关/共生死/硬链接/绑卡） | 零开发 |
| 模型分槽 | models.py:448 _MODULE_MODEL_SLOTS paint/manga-paint 分槽白名单 | 漫画加自己的槽位（默认走 manga-paint 槽） |
| 采样经验 | draw.py 语言感知路由/翻译兜底/负面词护栏/风格注入 | 分格 prompt 组装直接搬 |

**替代边界（退役清单）**：前端 components/paint/ 五组件 + usePaintStore + /paint 路由与侧栏项退役；后端 draw.py 中绘画页专属端点（history/favorite/批量删/result 轮询/controlnet 桩）随页退役。
**绝不能动的承重墙**（漫剧生图链共用）：image_queue / paint_engine / comfy_paint_engine / comfy_proc / gen_router；`/draw/status`（漫剧 waitPaintReady 与全局 PaintWarmup 组件在轮询它）、`/draw/models` 保留。
🔶 **拍板点 P1**：绘画历史数据（paint_history 表）是"迁移给漫画模块画廊"还是"随页退役保留只读"？倾向：保留只读一段过渡期。

## 三、阶段计划

| 阶段 | 内容 | 验收 |

| **M0（本日）** | 一致性 PoC：复用漫剧资产链生成角色立绘+四视图，验证"同角色多图"底座可用 | 端到端出图+产物落库 |
