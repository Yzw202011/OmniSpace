## 刀一：前端组件测试网（A0 档先行，为 Q11 拆巨石铺护栏）

**动机**：前端 147 文件仅 10 个纯逻辑测试（6.8%），vitest 只收 `.test.ts` 不收 `.tsx`，组件层零覆盖；而 Q11 要拆的 5 个 ≥900 行巨组件全在核心链路（问题总账 #38）。无护栏动拆 = 赌博。

### 1. 改动清单
| 文件 | 改什么 |
|---|---|
| `frontend/vitest.config.ts` | include 增加 `src/**/*.test.tsx`（环境仍 node，串行不变） |
| `frontend/src/components/model/ModelManager.test.tsx`（新） | A0 档护栏：mock services 层 → `react-dom/server` 的 `renderToStaticMarkup` 渲染冒烟（不炸+关键结构/文案存在） |
| `frontend/src/components/comic/ComicWorkspace.test.tsx`（新） | 同上 |
| `frontend/src/components/dialog/DialogView.test.tsx`（新） | 同上（含 store 初始态注入） |
| `frontend/src/components/manga/editor/StoryboardTable.test.tsx`（新） | 同上 |
| `frontend/src/components/novel/NovelPage.test.tsx`（新） | 同上 |

### 2. 影响面
只增测试与配置两行，**不动任何组件源码**；构建产物零影响；vitest 耗时 +数秒。A0 用 react-dom（已在依赖树）零新增依赖。

### 3. 验证方法
- `pnpm test` 全绿（原 10 个 + 新 5 个）；
- 护栏有效性反证：临时在某巨组件渲染里注入一个必炸表达式 → 对应测试红，还原后绿；
- `tsc --noEmit` 不因新测试文件报错。

### 4. 风险与回退
- 风险：个别组件 useEffect 访问 window/浏览器专属 API，static 渲染下抛错 → 该组件降级为「切片/工具函数测试」并在测试文件头注明跳过原因（不许静默 skip）。
- 回退：删 5 个测试文件 + 还原 vitest.config 两行，零残留。

### 待拍板
- **A0（本方案）**：零新依赖，静态渲染级护栏，半天~一天。
- **A1（二期，另立方案）**：引入 `@testing-library/react` + `jsdom` 做交互级测试——**涉及新增依赖，须单独拍板**。

## 刀三：训练三套队列收编 TaskQueueCore（防第四套出现）

**动机**：图像/视频已共用 TaskQueueCore（task_queue.py:70，B5 落地），但训练侧三套同构独立队列并存（lora_training_service.py:277、style_lora_service.py:164、character_lora_service.py:91——第三套 09-17 刚新增，复刻而非复用）。「加法快于减法」惯性如果不掐，第四套必现。

### 1. 改动清单
| 文件 | 改什么 |
|---|---|
| `src/services/task_queue.py` | 评估训练侧能力缺口（优先级语义/进度上报钩子）；缺口小则零改动直接复用，缺口大则最小增量补齐（预估 ≤80 行） |
| `src/services/character_lora_service.py` | :91 list 队列 + :261 worker → 换成 TaskQueueCore 宿主模式（对齐 image_queue.py:60 先例）；业务逻辑（数据集准备/训练循环/产物登记）不动 |
| `src/services/style_lora_service.py` | :164 PriorityQueue → 同上 |
| `src/services/lora_training_service.py` | :277 PriorityQueue → 同上 |
| `tests/unit/`（新 1~2 个文件） | 三服务排队/位次/取消语义回归（对齐 image_queue 测试模式） |

### 2. 影响面
- 仅训练三服务内部调度芯；API 面零变化；前端零感知。
- **上线窗口约束**：训练任务在跑时不可切换（需空闲窗口）；若并发会话在飞须先协调（§16.6）。
- 三服务分三个独立小批（3a character_lora → 3b style → 3c lora_training），每批独立验收独立回退。

### 3. 验证方法
- 单测绿；
- 实弹各一轮：人物 LoRA 训练走通「排队→执行→产物登记」全链；风格 LoRA 与知识训练各一轮冒烟；
- 观察队列位次广播与前端显示不回归（trainingApi.ts 消费面）。

### 4. 风险与回退
- 风险：TaskQueueCore 缺训练所需语义（如训练优先级抢占）→ 该服务本批暂缓，宁缓勿改语义（记录缺口，二期补）；
- 回退：逐服务独立 revert；因为是「换芯不换壳」，回退只涉及单文件。

### 待拍板
- 三小批顺序（推荐 newest first：character_lora 最新最简单 → style → lora）；
- 是否允许 task_queue.py 最小增量（若需要）。
