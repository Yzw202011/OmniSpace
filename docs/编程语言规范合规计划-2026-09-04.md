## 一、目标与硬边界

**目标一句话**：把审计查出的 8 类缺口分五批清掉，让项目对《编程语言规范》的适用条款从「高压线全绿、细节有欠账」变成「全绿 + 例外清单在案」，全程功能零变化。

**功能零影响的四道保险**：
1. **只做「装饰性改动」**：加类型注解、加运行时校验、改 CSS 动画属性、加 lint 规则——不碰数据层、不碰 AI 引擎、不碰网络协议、不碰启动链。
2. **每批独立 commit，可单独回滚**（.githooks 已有 ruff 三闸，入库即过闸）。
3. **每批必过通用验收闸门（§四），不绿不入库**。
4. **每批动工前重读热点文件**（并发会话可能正在飞代码，先重读再动手——既有铁律）。

**明确不做清单（诚实划界，这些做了才会影响功能）**：

| 不做的事 | 理由 |
|---|---|
| sqlite3 → aiosqlite 全量迁移 | 8 文件牵动 319 个端点的数据层，回归风险远大于收益；现状 WAL+写锁+单实例已兜住，288 测试全绿。**建议记为规范例外 E1** |
| /dialog/stream WS → SSE 存量迁移 | 对话流是核心功能，迁移动动静；只约束**新增**代码不再用 WS 传 token 流（例外 E2） |
| 发码台内置密码移除 | 用户拍板的设计（E3），不动 |
| Rust/Tauri/C++/React Compiler 等作废章节 | 技术不存在，不为「合规」复活 |
