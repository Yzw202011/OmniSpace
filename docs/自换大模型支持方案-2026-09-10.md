## 一、问题陈述

产品形态：用户自行下载大模型 → 拖入 `models/` → 在项目中使用（对话类已天然成立：动态发现 + 白名单）。

**断裂点（2026-09-10 代码级核实）**：视觉生成（全部图片 + 全部视频）走 ComfyUI，而工作流是按**登记模型定制**的——

| 断裂点 | 证据 | 用户遭遇 |
|---|---|---|
| 绘画引擎单模型蓝图 | `comfy_paint_engine._build_workflow`：Flux.2 Klein 专属节点链，`_PAINT_FILES` 写死 unet/clip/vae 文件名 | 拖 SDXL 底模进来 → 模块配置加白名单 → 选用 → 工作流仍加载 Klein 或报文件缺失 |
| 视频链单模型 | `VIDEO_ROUTING_TABLE` 仅 H3；`h3_chain_workflow_api.json` 写死 H3 模型名 | 拖 Wan/LTX → 同上，ComfyUI 天书报错 |
| ComfyUI 隔离（好消息） | ComfyUI 模型树按已知模型硬链接管理，不扫 `models/video_gen/` | **ComfyUI 本身不会被外来模型弄坏**；坏的只是用户体验 |
| 误导性展示 | 模型扫描把 wan2/ltx/cogvideo 等归类 VIDEO，管理页看起来"能用" | 用户以为支持，实际不可用 |

## 二、现状架构事实（方案依据）

1. **走 ComfyUI**：绘画页出图 / 漫剧关键帧 / 漫剧资产图（含 PuLID）/ AI 漫画 / 漫剧视频 H3 链（HTTP API :8189）。
2. **不走 ComfyUI**：对话/写作台/漫剧文字（transformers/vLLM/llama-server）、训练、语音。
3. **历史工作流无残存**：仓库内仅 `h3_chain_workflow_api.json`；wan21/wan22/ltx 权重在盘（`models/video_gen/`）但无对应工作流模板。
4. **模块白名单机制现成**：`PUT /models/module-config`（slot→allowed/default，即时生效）——用户可自行把外来模型加进白名单，这是护栏必须拦截的入口。

## 三、阶段 1：护栏 + 登记台（止血，小活）

**目标**：任何外来模型拖入后不出天书错误；"能用/待接入"一目了然。

### 改动清单

| # | 文件 | 改动 | 约行数 |
|---|---|---|---|
| 1 | `src/api/models.py` | 模型列表端点为 VIDEO/VISION 类模型增加 `chain_ready` 字段（按路由表/注册集计算：video∈VIDEO_ROUTING_TABLE、paint∈PAINT 注册集） | +25 |
| 2 | `src/api/draw.py` | `_submit_task` 入口：解析出的模型 ∉ 绘画注册集 → `ApiError`（40004 语义）「该模型已入库，但绘画链路目前支持 Klein/Qwen-Image，自定义模型接入将在后续版本开放」 | +15 |
| 3 | `src/api/manga/video.py` | 视频生成入口（模型解析处）：∉ 视频注册集 → 同款友好拒绝（H3 为当前唯一注册） | +15 |
| 4 | `frontend/src/components/model/ModelManager.tsx` | VIDEO/VISION 类且 `chain_ready=false` → 徽标「已入库 · 生成链路暂未接入」 | +20 |
| 5 | `models/README.txt`（新增） | 目录约定与当前支持范围说明 | 文档 |
| 6 | `tests/unit/unit/test_foreign_model_guardrail.py`（新增） | ①外来模型 chain_ready=false ②draw/video 入口拦截+文案 ③注册模型放行（哨兵防误伤） | ~90 |

**不碰**：H3 链路、VIDEO_ROUTING_TABLE、任何工作流、绘画/视频生成逻辑本体（纯前置拦截）。

### 影响面
- 白名单保存保持宽松（声明式管控不收紧）；拦截在生成入口——用户改白名单的行为不变，只是误用时得到诚实反馈。
- `chain_ready` 为新增只读字段，前端旧版忽略无碍。

### 验证方法
- 单测：上述 3 组哨兵全绿；
- 实弹：把 wan22-ti2v-5b 加入 manga-video 白名单并选为默认 → 漫剧生成 → 收到友好提示（非 ComfyUI 报错）；绘画同理；H3 正常生成不受影响（回归）。

### 风险与回退
- 最大风险：拦截条件误伤注册模型（如别名/stem 差异）→ 哨兵测试③锁定；判定函数集中一处（`visual_chain_supported(model_id)`）。
- 回退：删两处拦截 + chain_ready 字段即净，零数据影响。

## 四、阶段 2：绘画页自定义图片模型（中活）

**目标**：拖 SD1.5 / SDXL 系底模 → 绘画页「自定义」分组出现 → 直接出图。

### 设计要点
1. **目录约定**：`models/custom_image/<名称>/`（.safetensors/.ckpt 单文件或目录）；模型扫描纳入。
2. **家族探测**：文件名/体积/config 特征 → `sd15` / `sdxl`；Flux 系 v1 判「完整包才支持」（需含专属 clip/vae 组件），其余判不支持并如实标注。
3. **通用工作流模板**（comfy_paint_engine 新增分支，不动 Klein 蓝图）：`CheckpointLoaderSimple（文件名注入）→ CLIPTextEncode(±) → KSampler → VAEDecode → SaveImage`；SDXL 默认 1024²、SD15 512²（分辨率白名单钳制）；采样器映射表。
4. **ComfyUI 挂接**：新模型自动硬链接进 ComfyUI `models/checkpoints`（扩展 comfy_link 逻辑，同盘零磁盘代价）。
5. **绘画页前端**：模型下拉新增「自定义模型」分组（`/draw/models` 扩展 custom 通道）；选择自定义模型时隐藏 Flux 专属参数（参考图多参考/PuLID/图像编辑模式）。
6. **边界（防破一致性体系）**：**只开放绘画页**；漫剧关键帧/资产/AI 漫画链保持锁定（PuLID/风格包按登记底模调校，换底模即破）。缺 VAE 的 SDXL 用内置 VAE 兜底。LoRA 挂载、Refiner、图生图 v1 不做（v2 评估）。

### 坑清单（预先锁定）
- 外来 fp16/fp8 变体兼容性（ComfyUI 原生支持，需实测抽样）；
- 文件名含中文/空格的挂接路径处理；
- 超大 checkpoint（>10GB）的显存准入提示（16GB 卡 SDXL 上限实弹标定）。

## 五、阶段 3：视频模型开放（重活，按家族逐个接）

**目标**：外来视频模型作为**可选档**可用；H3 仍为默认主力（D2 已拍板）。

### 设计要点
1. **存量结论**：无历史工作流可复活，每家族 greenfield；盘上已有 wan21-i2v/wan21-vace/wan22-ti2v-5b/ltx-0.9.5 权重可复用。
2. **每家族接入包**（一个工作单元/家族）：ComfyUI 官方模板起步的工作流（API 格式）→ 参数映射（时长/分辨率/首帧/运动强度）→ 显存准入档案 → 实弹调校（质量+速度基准）→ 四段方案单独拍板。
3. **建议顺序**：Wan2.2-ti2v（盘上权重 + 社区最活跃）→ LTX-0.9.5 → 按用户需求增补。
4. **H3 共存**：视频下拉 = H3（默认，置顶标注"主力"）+ 已接入家族；`VIDEO_ROUTING_TABLE` H3 条目不动，新增家族走独立注册（锁定令合规）。
5. **与阶段 2 的关系**：视频家族多为单文件/组件包，同样走「目录约定 + 家族探测 + 通道挂接」，复用阶段 2 的基建。

## 六、统一验收标准（全阶段通用）

1. 真浏览器全链实弹：拖入 → 管理页可见（带正确状态徽标）→ 下拉出现 → 选用 → 生成出图/出片 → 质量抽检；
2. 哨兵单测：注册模型永不被误拦；外来模型拦截文案含出路；
3. H3/现有 Klein 链回归全绿（锁定令合规证明）；
4. 每阶段独立 commit 边界，回退 = 删该阶段增量。
