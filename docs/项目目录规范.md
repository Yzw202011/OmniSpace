> 版本：v1.0（2026-09-01 拍板：方案 A = 文档 + 审计脚本 + 存量清理清单）
> 配套审计工具：`scripts/dir_audit.py`（一条命令体检，见 §6）
> 适用：`E:\OmniSpace` 项目根及全部子目录；对封装发行（v5 计划）同样生效

## §1 顶层目录白名单制

顶层只允许下列目录存在。**白名单之外新建目录必须先在本表登记**（提 PR 改本文档），否则审计报违规。

### 1.1 源码与工具链（进 git）

| 目录 | 用途 | 进发行包 |
|---|---|---|
| `backend/` | FastAPI 后端源码（Python 3.10） | ✅ |
| `frontend/` | React 前端源码（`dist/` 为构建产物，随构建更新） | ✅（dist） |
| `launcher/` | 启动链（boot.py / stop.py / splash / 快捷方式生成） | ✅ |
| `scripts/` | 运维与构建脚本；**临时调试脚本一律进 `scripts/scratch/`** | 部分 |
| `skills/` | H3 / 漫剧技能插件（标准插座体系） | ✅ |
| `license_console/` | 授权管理台源码（六道锁体系） | 独立发行 |
| `packaging_console/` | 封装打包台（卖家自用 GUI，FastAPI+pywebview；`builds/`+`config.json` 为本地产物不入库） | ❌ **红线：绝不随发行包分发** |
| `build_tools/` | PyInstaller 打包工具与 spec | ❌ |
| `tests/` + `backend/tests/` | pytest 测试 | ❌ |
| `docs/` | 全部文档（真源层级见 CLAUDE.md §14）；截图进 `docs/assets/` | ✅ |
| `tools/`（除 ComfyUI） | 下载器等外部工具脚本 | 部分 |

### 1.2 资产与运行时（不进 git）

| 目录 | 用途 | 约束 |
|---|---|---|
| `models/` | **模型资产唯一真源**，按品类分区（见 §2） | 不进 git；发行按显卡套餐裁剪 |
| `tools/ComfyUI_windows_portable/` | ComfyUI 便携版（懒加载子进程） | 大权重必须硬链接挂接（见 §2.3） |

| `pydeps/` | 发行依赖缓存（白名单打包源） | 不进 git |
| `ffmpeg/` | ffmpeg 二进制 | 不进 git |
| `keys/` | 授权密钥（Ed25519 等） | 不进 git；发行时密封注入 |

| `.cache/` `.pytest_cache/` `.ruff_cache/` `.githooks/` `.vscode/` `.mimosa/` `.zcode/` | 工具缓存 | 自动生成，免审 |

## §2 模型资产规范（346GB 大头，规矩最严）

### 2.1 分区与命名

```
models/
  dialog/          对话/多模态（qwen3-vl 系等）
  paint/           绘画底座（flux2-klein / sdxl / qwen-image + loras）
  video_gen/       视频生成（h3 / ltx / wan 系）
  3d/              3D 重建（TripoSR）
  voice/ 等        语音组件按现有目录
  <顶层散文件>      GGUF 单文件（扫描层以 stem 为 id 识别）
```

- 目录名 = 模型 id（磁盘扫描、引擎候选表、模块配置三处同命名空间，**改名=改 id，慎动**）
- 新模型入库两条正规路：
  1. **模型管理页「导入模型」**（2026-09-01 完整接入：自动分类/大小/显存估算，外部路径原地登记不搬运）
  2. 下载到 `models/` 对应分区后靠自动发现层接管（必须通过 100MB 权重门槛）
- 任何"从别处拷个目录进来"的操作，入库后必须用 §6 审计扫一遍重复副本

### 2.2 删模型铁律（血泪教训汇编）

删任何模型前必查：
1. 引用扫描：`grep -r <模型名> backend/ frontend/src/ tools/*.py`（引擎候选表/白名单/工作流 JSON 三处）
2. ComfyUI 侧硬链接：`fsutil hardlink list <文件>`（**删一端不释放空间**，要释放须两端同删）
3. 双栈检查：vLLM（py313）与 transformers（py310）可能引用不同变体（awq / int4 / nvfp4）
4. 漫剧 V8 工作流引用的 Ref2VA 变体与 h3_engine 的 FL2VA 变体**都在用**

### 2.3 ComfyUI 硬链接挂接（禁独立副本）

- ComfyUI（`tools/.../ComfyUI/models/`）消费的**每一个 ≥1GB 权重**，凡项目 `models/` 已有同名资产的，必须硬链接挂接（同 inode），**禁止二次下载成独立副本**
- 挂接工具：`os.link`（同盘）；真源在 `scripts/comfy_link/link_comfy_models.py`（打包时包内仍落 `modelxiazai/`，交付物路径不变）
- 例外登记：仅 ComfyUI 使用的 TE（如 `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`）允许只在 ComfyUI 侧一份
- 已知违规存量（清理清单第一批）：H3 双 VAE（video 5.2G + audio 0.6G）双端独立副本

## §3 运行时产物规范

| 产物 | 归宿 | 生命周期 |
|---|---|---|
| 后端/启动器日志 | `logs/` | 10M×5 自动轮转（方案 C），异常大文件审计报警 |
| vLLM 日志 | `logs/vllm-server.log` | 单调追加，切换引擎按需清 |
| ComfyUI 产物 | `tools/.../ComfyUI/output/` | 漫剧 h3_chains 验收产物定期归档或删 |
| 诊断导出包 | `logs/`（方案 C 导出） | 用后即删 |
| 临时文件 | `scripts/scratch/` 或系统 TEMP | **根目录禁止 tmp 文件过夜** |

## §4 构建与发行规范

- `frontend/dist/`：vite 构建产物（NoCache 静态托管，改前端必重建，构建命令见 CLAUDE.md）
- `dist_out/`：PyInstaller 打包输出，**可随时整目录删除重建**；金母版基线另行封存不占工作区
- `pydeps/`：发行依赖缓存 = 白名单打包源，勿当临时下载区
- 发行裁剪以 `docs/封装发行方案` 系列为准（显卡套餐 / 模型三通道）

---

## §5 根目录卫生红线

1. 调试/探针脚本（`_tmp_*.py`、`_sandbox_*.py` 类）→ 一律进 `scripts/scratch/`（已 gitignore），用过即删
2. 截图/素材 → `docs/assets/`（git 例外白名单已配）或 `采集素材/`（保留为登记目录）
3. 临时 txt（`tmp_*.txt`）→ 用完即删；**密钥类明文文件（tmp_key.txt）发现即删并检查泄露面**
4. 命名规范：新目录用英文小写连字符；拼音（modelxiazai）、拼写错误（omnipspace-demo）不得再犯
5. exe/二进制不放根目录（`Omnispace.exe` 去向见清理清单）

## §6 审计与执行

```bash
runtime/py310/python.exe scripts/dir_audit.py            # 全量体检（大白话报告）
runtime/py310/python.exe scripts/dir_audit.py --json     # 机读输出（供 CI/自动化）
runtime/py310/python.exe scripts/dir_audit.py --skip-models   # 跳过 ComfyUI 大扫描（秒出）
```

审计项：
1. 根目录散件（§1.3 白名单外）
2. 顶层目录白名单外目录（§1）
3. ComfyUI ↔ models 重复副本（同名 ≥1GB：同 inode=合规挂接；同大小不同 inode=可零风险合并；不同大小=版本冲突须人工裁定）
4. `logs/` 异常大文件、`ComfyUI/output/` 体积播报

退出码：0=干净，1=有违规（未来挂 pre-commit 的挂点）。

**存量违规不追溯处罚，但清理清单拍板后须在两周内归零；新增违规=当次修复。**
