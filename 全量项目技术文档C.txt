1.2 六大核心模块 + 五大智能引擎
六大核心模块
1.AI 对话 — 基于 Qwen3-VL-8B/4B/2B 模型，支持多模态对话，RAG 检索增强
2.AI 绘画 — 集成 FLUX.1-dev / Kolors 2.1 / SDXL，支持 ControlNet 与 IP-Adapter
3.漫剧创作 — 分镜表 + 3D 导演台（Three.js r170）+ 视频生成（LTX-2 / Wan2.1 / CogVideoX）
4.知识学习（v2.3 新增） — 自主学习引擎（内置 CEF 浏览器 + AI Agent + LoRA 进化）
5.模型管理 — ~392GB 模型库 + 三方协同调度
6.视频风格 — LTX-2 LoRA 微调引擎，支持用户自定义视频风格
五大智能引擎
1.LTX-2 LoRA 微调引擎 — 用户自定义视频风格，QLoRA 4bit 量化增量训练
2.模型预加载 ML 预测引擎 — 基于 XGBoost 预测用户下一个可能使用的功能，提前加载模型至 GPU
3.协同调度历史学习引擎 — 记录每次调度决策与效果，自适应调整预加载阈值
4.AV1 硬件编码引擎 — RTX 50 系优先 NVENC 硬编，RTX 30/40 系 NVENC 硬编，AMD/CPU 使用 SVT-AV1 软编
5.自主学习引擎（v2.3 新增） — 内置 CEF 浏览器 + AI 自主浏览学习 + 知识反哺（RAG + LoRA 双层）

[训练触发条件检测]

    ├── 学习率：2e-5

第四章 调整方案
4.1 性能自适应调整
检测条件	调整动作
GPU 显存 > 90%	降低模型精度 / 卸载非活跃模型
GPU 利用率 > 95% 持续 10s	降低生成质量参数
CPU > 90%	暂停后台学习 / 降低标签页数
内存 > 85%	清理缓存 / 减少 ChromaDB 缓存
磁盘 IO > 80%	延迟非关键写入
网络带宽 > 设定上限	降低学习速率
4.2 硬件等级自适应
硬件等级	对话模型	绘画模型	视频模型	学习标签数
RTX 5090 32GB	Qwen3-VL-8B	FLUX.1-dev	LTX-2	5
RTX 4090 24GB	Qwen3-VL-8B	FLUX.1-dev	LTX-2	5
RTX 4070Ti 12GB	Qwen3-VL-4B	Kolors 2.1	Wan2.1-1.3B	3
RTX 3060 12GB	Qwen3-VL-2B	SDXL	CogVideoX-2B	2
AMD RX 6600	Qwen3-VL-2B	SDXL	CogVideoX-2B	1
纯 CPU 32GB	Qwen3-VL-2B	SDXL（慢）	不可用	1
4.3 学习策略调整
条件	调整
知识库接近 10 万条	提高去重阈值（0.85→0.8）
LoRA 训练连续 3 次质量下降	暂停自动训练，通知用户
网络学习连续 5 页无有效知识	切换搜索策略/关键词
行为数据 < 50 条	不触发微调
用户长时间未使用某功能	降低该功能相关学习优先级

5.5 v2.3.1 新增优化任务（五项待优化项专项）
TASK-LEARN-006：混合检索系统（Hybrid Search）
目标：提升 RAG 检索精度，解决专有名词、代码等精确匹配问题。
技术约束： - 引入全文搜索引擎（SQLite FTS5） - 保持与现有 ChromaDB 向量检索的并行调用
实现要求： 1. 修改 KnowledgeProcessingService，在知识入库时，同步将内容写入全文搜索引擎 2. 重构 KnowledgeInjectionService.retrieve 方法，实现双路召回（向量 + 关键词） 3. 实现 RRF（Reciprocal Rank Fusion）算法对两路结果进行融合重排序 - 公式：score = 1 / (k + rank_vector) + 1 / (k + rank_keyword) - k 为常数，通常取 60 4. 高级方案：使用 Cross-Encoder 模型（如 bge-reranker）对合并后的候选集（前50个）进行精细化重打分
验收标准： - 在包含专有名词的测试集上，检索命中率（Hit Rate）提升 > 15% - 检索延迟增加 < 20ms
TASK-LEARN-007：Agent 分级决策机制
目标：优化 AI 浏览 Agent 决策速度，减少不必要的视觉理解开销。
技术约束： - 引入轻量级页面分类器（基于规则或小型 ML 模型） - 不降低复杂页面的决策准确率
实现要求： 1. 在 BrowserAgentService 中新增 classify_page 方法 2. 页面复杂度分类器特征： - DOM 结构：<form> 标签数量、<input> 类型、<button> 数量 - 内容密度：文本与 HTML 标签的比例 - 样式特征：是否存在大量 onclick 事件或复杂的 CSS 类名 3. 分级决策流程： - 简单页面（博客/新闻/文档）：跳过截图和 Qwen3-VL 视觉分析，仅基于 DOM 解析的文本进行快速决策，可使用 Qwen3-4B 加速 - 复杂页面（Web App/后台管理/社交媒体）：维持原有”DOM + 视觉”双模决策流程
验收标准： - 简单页面的单次决策时间从 ~3s 降低至 < 500ms - 复杂页面的决策准确率无明显下降
TASK-LEARN-008：LoRA 训练加速
目标：将 LoRA 微调时间从 30min-2h 缩短至 15min-1h。
技术约束： - 利用 Flash Attention-2 优化注意力计算 - 使用 8-bit 优化器减少显存占用
实现要求： 1. 在 LoRATrainingService 中，配置模型加载时启用 attn_implementation="flash_attention_2" 2. 将优化器从 AdamW 替换为 bitsandbytes 库提供的 AdamW 8-bit 或 PagedAdamW 3. 优化 DataLoader，设置 num_workers > 0 和 pin_memory=True 4. 使用 cosine_with_restarts 或 polynomial 学习率调度器 5. 在显存允许的情况下增大 gradient_accumulation_steps 6. 使用 accelerate 配置启用 DeepSpeed ZeRO-2 或 ZeRO-3 阶段
验收标准： - 在相同数据集和硬件条件下，单 epoch 训练时间减少 > 30% - 最终模型的困惑度（Perplexity）和生成质量无下降
TASK-LEARN-009：浏览器进程池
目标：优化内置浏览器启动速度，实现”秒开”体验。
技术约束： - 在应用启动时预初始化浏览器进程 - 确保进程复用时的状态隔离（Cookie、缓存清除）
实现要求： 1. 创建 BrowserPool 服务，在 app/main.py 启动事件中初始化空闲的 CEF 浏览器进程 2. 修改 AutonomousLearningService，从 BrowserPool 获取/归还浏览器实例 3. 实现会话结束后的状态清理逻辑（清除 Cookie、LocalStorage、缓存） 4. 实现会话快照与恢复：保存”干净”快照，后续启动直接恢复
验收标准： - 学习会话启动时，浏览器就绪时间从 < 3s 降低至 < 1s - 不同学习会话之间无 Cookie 或缓存数据泄露
TASK-LEARN-010：知识图谱可视化
目标：提供知识关联的可视化视图，增强用户对知识库的理解。
技术约束： - 前端使用 react-flow 或 cytoscape.js 进行渲染 - 后端使用 networkx 或轻量级图数据库存储关系
实现要求： 1. 在 KnowledgeProcessingService.extract_knowledge 中，增加实体关系三元组（实体1, 关系, 实体2）的抽取 2. 新增图数据存储模块，保存抽取的实体和关系 3. 新增后端 API GET /api/v1/learn/knowledge/graph，根据知识 ID 返回关联的节点和边数据 4. 在前端 KnowledgeBrowser 组件中，增加”图谱视图”切换功能 5. 支持节点拖拽、缩放和点击查看详情
验收标准： - 能够成功从知识内容中抽取实体关系 - 前端能正确渲染知识图谱，支持节点拖拽、缩放和点击查看详情

8.3 全部模块原理与实现细节
8.3.1 AI 对话模块
原理：基于 Qwen3-VL 多模态大模型，支持文本和图片输入，流式输出。集成 RAG 检索增强生成，从本地知识库检索相关知识注入 Prompt。
实现细节： - 模型选择逻辑：GPU显存>=24GB→Qwen3-VL-8B(fp16)，>=16GB→Qwen3-VL-8B(int8)，>=10GB→Qwen3-VL-4B(int8)，<10GB→Qwen3-VL-2B(int8) - RAG检索：BGE-large-zh向量化→ChromaDB相似度检索Top-5→过滤score<0.5→格式化注入Prompt - 被动补全：检测模型不确定性→提取关键词→快速搜索→补充上下文重新推理 - 流式输出：SSE（Server-Sent Events）逐token返回 - 上下文窗口：最近N轮，默认8192 token
8.3.2 AI 绘画模块
原理：集成 FLUX.1-dev / Kolors 2.1 / SDXL 三大生图模型，支持文生图、图生图、超分。集成 ControlNet 空间控制、IP-Adapter 风格迁移、LoRA 风格应用。
实现细节： - 模型选择：显存>=16GB→FLUX.1-dev，>=12GB→Kolors 2.1，<12GB→SDXL - 生成参数：步数20~50（默认30），CFG 515（默认7.5），尺寸5122048 - Prompt优化（v2.3）：ChromaDB检索相关风格知识→提取优化建议→自动补充prompt - 异步任务：生成任务提交到Celery，WebSocket推送进度 - 后处理：Real-ESRGAN超分
8.3.3 漫剧创作模块
【7步操作流程（详见OmniComic完整需求规格说明书）】：创建项目→导入剧本→自动/手动分镜→生成资产图(角色/场景/道具)+角色音色绑定→分镜描述词→导演台操作→视频生成
原理：分镜表管理 + 3D导演台场景编辑 + 视频生成管线。分镜包含场景描述、镜头语言、角色、动作、时长、转场等完整元数据。3D导演台基于Three.js实现实时3D场景预览。
实现细节： - 角色多视图设定图：4096×1024横排4格（正面/侧面/背面/特写），FLUX.1-dev单次生成，IP-Adapter统一seed保证风格一致性，后处理自动裁切+一致性校验 - 角色音色绑定：1个默认音色+N个情感音色（如高兴/悲伤/愤怒）两层结构，CosyVoice3/GPT-SoVITS驱动 - 导演台自动资产拉取：选中分镜→自动拉取对应角色图/场景图/道具图→3D场景生成 - 视频三路输入：分镜图+资产图+描述词→视频生成模型 - 四分镜合一图：四视图合并展示，便于导演台整体预览 - 分镜数据模型：id/project_id/order/scene_description/camera/angle/movement/characters/expression/action/duration/transition/music/preview_image/video_clip/knowledge_refs - AI描述生成：RAG检索相关领域知识→注入Prompt→Qwen3-VL生成专业化场景描述 - 3D导演台：Three.js r170 + @react-three/fiber + @react-three/drei，支持对象放置/拖拽/旋转/缩放、相机控制（轨道控制器）、灯光设置、截图导出 - 与分镜表联动：选中分镜→3D场景加载对应布局，调整3D场景→更新分镜描述
8.3.4 视频生成模块
原理：基于 LTX-2 / Wan2.1 / CogVideoX 视频生成模型，逐分镜生成视频片段，应用LoRA风格，AV1/H.264/H.265编码导出。
实现细节： - 模型选择：根据GPU显存自动选择LTX-2（高配）/Wan2.1-1.3B（中配）/CogVideoX-2B（基线） - LoRA风格应用：在视频生成时注入LoRA权重 - AV1编码调度：RTX 50系→NVENC AV1硬编，RTX 30/40系→NVENC H.264硬编，AMD→SVT-AV1软编，纯CPU→SVT-AV1软编 - 编码参数：CRF 23，预设medium，AAC 256kbps - 失败降级：AV1→H.264自动降级
8.3.5 知识学习模块（v2.3核心）
原理：内置 CEF 浏览器（Chromium 120+），AI Agent 像人一样操作浏览器（搜索/点击/翻页/阅读），通过 RAG+LoRA 双层机制反哺本地大模型。
实现细节： - CEF浏览器：cefpython3绑定，支持多标签页（最多5个）、广告过滤（EasyList）、安全层（禁止登录/下载/非HTTP协议） - AI浏览Agent决策循环：感知→理解→决策→执行→提取→评估，使用Qwen3-VL进行多模态推理 - 双模式感知：DOM解析（<100ms）+ 视觉理解（~3秒），根据页面复杂度自动选择 - 知识处理管线：内容过滤→分段→知识提取→质量评估→SimHash去重→BGE向量化→ChromaDB入库 - 双层知识注入：RAG层（秒级生效，ChromaDB检索Top-5）+ LoRA层（小时~周级生效，QLoRA增量微调）
8.3.6 模型管理模块
原理：统一管理~392GB模型库的加载、卸载、切换、预加载。基于GPU显存智能分配，支持ML预测预加载。
实现细节： - 模型生命周期：加载→运行→卸载/预加载 - 显存管理：实时监控GPU显存，空闲显存>=所需显存则直接加载，否则检查可卸载模型 - ML预测预加载：XGBoost模型预测用户下一个可能使用的功能（概率>0.7触发），提前加载模型到GPU - 协同调度历史学习：记录每次调度决策与效果，自适应调整预加载阈值
8.3.7 视频风格模块（LoRA微调）
原理：用户通过上传视频片段/图片训练自定义LoRA风格，应用于视频生成。基于QLoRA 4bit量化实现低显存训练。
实现细节： - 基座模型：Qwen3-14B / ChatGLM-4-9B - QLoRA 4bit量化 - LoRA rank=16, alpha=32 - 学习率：2e-5，Epochs：3（可配置） - 增量训练：在上一版LoRA基础上继续 - 质量评估：困惑度+生成质量+领域相关性 - 版本管理：支持多版本并存和回滚
8.4 模块间协调机制
8.4.1 大模型互斥机制
当AI对话、AI绘画、漫剧视频生成、LoRA训练等高资源占用功能运行时，其他冲突功能在UI上置灰不可用。浏览器学习和行为学习作为后台低优先级服务，不影响任何前台功能。
8.4.2 资源调度协调
?优先级队列：P0（用户操作）> P1（模型预加载）> P2（LoRA训练）> P3（浏览器学习）> P4（行为学习记录）> P5（知识库清理）
?资源配额：根据用户状态（空闲/创作/推理中/断网/电池模式）动态调整学习引擎的资源占用
?自动调整：GPU显存>90%→降低精度/卸载模型；CPU>90%→暂停后台学习；内存>85%→清理缓存
8.4.3 知识反哺协调
知识从三个来源产生（网络学习、行为学习、文档导入），经过处理后存入ChromaDB和训练队列。消费端包括AI对话（RAG检索）、AI绘画（Prompt优化）、漫剧分镜（知识注入）、导演台（场景参考）、视频生成（风格参考）。当训练数据>=100条时自动触发LoRA微调，新LoRA注册后全部功能可使用。
8.4.4 前后端通信机制
Tauri 2.x IPC 通信规范（依据文档C 3.2.1节）：
- 通信协议：JSON 序列化，字段命名使用 camelCase
- 类型校验：前端使用 Zod schema 运行时校验，后端使用 Rust serde 编译时校验
- 请求模式：invoke（请求-响应）+ event（事件推送）双通道
- 错误处理：统一返回 {success, data, error, meta} 格式
- 性能约束：IPC 单次调用 < 5ms，事件推送延迟 < 50ms

HTTP REST + WebSocket 通信：
?HTTP REST（JSON）：常规请求/响应，Pydantic v2自动校验+OpenAPI文档生成，openapi-typescript自动生成TS类型
?WebSocket（JSON）：实时进度推送、日志推送、状态通知，支持按module订阅
?文件上传/下载：multipart/form-data + 流式响应
?错误统一格式：{success: false, error: {code: "MODEL_NOT_LOADED", message: "描述", detail: "详情", suggestion: "修复建议"}, meta: {...}}
8.4.5 跨语言调用关系

9.2.2 TypeScript 5.x 规范（含Zod运行时校验）
类型安全三层保障：
1. 编译时：TypeScript 5.x 严格模式（strict: true）
2. 运行时：Zod schema 校验所有外部输入（API响应、IPC消息、用户输入）
3. 边界：Zod schema 与 Python Pydantic / Rust serde 模型保持一致

Zod 使用规范：
- 所有 API 响应和 IPC 消息必须定义 Zod schema
- 使用 z.object() 定义结构，z.enum() 定义枚举，z.string().uuid() 校验UUID
- 错误码使用 Zod 枚举：z.enum(["MODEL_NOT_LOADED", "VRAM_INSUFFICIENT", "KNOWLEDGE_VECTOR_TIMEOUT", ...])
- 禁止使用 z.any() 和 z.unknown()，必须精确描述类型

职责边界： - 负责：UI渲染、用户交互、3D场景实时预览、状态管理、WebSocket消息接收与展示、表单校验、本地缓存 - 不负责：AI模型推理、文件I/O、视频编解码、数据库操作、进程管理
禁止事项： - 禁止执行AI推理或>100ms同步计算 - 禁止any类型（@typescript-eslint/no-explicit-any: error） - 禁止直接访问文件系统或数据库 - 禁止在前端持有>50MB的Buffer
编码铁律（依据文档C）：所有组件必须使用函数式组件 + Hooks，所有外部数据必须经过 Zod 校验，所有异步操作必须有错误处理（try-catch 或 error boundary）
9.2.3 Python 3.12 规范
职责边界： - 负责：REST API服务、AI推理编排、任务调度、知识处理管线、AI Agent决策循环、CEF浏览器控制、模型生命周期管理、数据库ORM操作、配置管理与系统监控、WebSocket推送 - 不负责：GPU Kernel编写、像素级图像处理热路径、视频编解码、浏览器渲染、前端UI渲染
禁止事项： - 禁止在FastAPI路由函数中直接调用模型推理（阻塞事件循环） - 禁止使用time.sleep()（用asyncio.sleep()） - 禁止裸except:（必须捕获具体异常类型） - 禁止纯Python循环处理像素/大数组（GIL+解释器开销）
编码铁律（依据文档C）：所有异步函数必须使用 async/await，所有数据模型必须继承 Pydantic BaseModel，所有路由函数必须有类型注解和 docstring
9.2.4 C/C++ 规范
职责边界： - 负责：CEF浏览器引擎、FFmpeg编解码、图像处理算子、SimHash/MinHash去重算法、GPU显存监控、系统级资源管理、SQLite原生引擎 - 不负责：业务逻辑、AI模型推理编排、用户界面、网络协议解析、配置管理
禁止事项： - 禁止在C++层写任何业务逻辑 - 禁止在C++层直接操作数据库 - 禁止在C++层管理模型生命周期
编码铁律（依据文档C）：所有公开接口必须使用 RAII 管理资源，禁止裸指针传递所有权，所有 C API 必须有错误码返回
9.2.5 CUDA C++ 规范
禁止事项： - 禁止在CUDA Kernel中写业务判断逻辑 - 禁止Kernel中动态分配内存（用预分配workspace） - 禁止跨GPU同步（单卡推理） - 自定义Kernel必须提供CPU fallback
9.2.6 Rust 规范
适用模块： 1. Tauri 2.x 原生壳层（窗口管理、IPC通信、系统托盘、全局快捷键） 2. 浏览器进程池管理（CEF进程生命周期） 3. 图像批处理（resize/crop/format convert） 4. SimHash/MinHash批量去重 5. 文本分段器（按标题/语义切分） 6. 向量距离批量计算 7. 日志/行为数据高速写入（无锁环形缓冲）
禁止事项： - 禁止在Rust侧调用Python（单向调用，避免循环依赖）
编码铁律（依据文档C）：所有公开函数必须有 #[must_use] 或明确错误处理，禁止 unwrap() 在非测试代码中使用，所有 IPC handler 必须使用 serde 校验
9.2.7 SQL 规范
规范： - 所有表必须有created_at/updated_at - 高频查询必须建索引 - 禁止在SQL中写业务逻辑（CASE WHEN复杂判断） - 禁止SELECT *（必须显式列名） - 禁止在SQLite中存储>1MB的BLOB
